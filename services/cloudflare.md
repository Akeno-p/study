# Cloudflareとは

**自分のサーバーの手前に置くサービス(CDN, WAF, DDos対策, CDN、WAF、DDoS対策 など)をまとめて提供している会社。またはその機能そのもの。**

## Cloudflareのサービスは4種類

手前に置くサービスが中心だが、それ以外の種類もある。

| 種類                           | 内容                                                                                                     | 自分のサーバー      |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | ------------------- |
| 手前に置くサービス             | CDN、WAF、DDoS対策、Load Balancing                                                                       | 必要                |
| Cloudflareの上で動かすサービス | サイトやプログラムをCloudflareのサーバーで動かす（Pages、Workers）。ファイル置き場（R2）やDB（D1）もある | 不要                |
| ドメインの取得と管理           | ドメインを買う（Cloudflare Registrar）、ドメインの設定を管理する                                         | どちらでも          |
| 企業の社内ネットワーク向け     | 社員が社外から社内システムに安全に接続する仕組みなど                                                     | Webサイトとは別の話 |

「Cloudflareの上で動かすサービス」は、VPSを借りずにCloudflareだけでWebアプリを動かせるもので、AWSのEC2・S3・RDSなどと同じ領域で競合している。

## 同じことができる会社は他にもある

大きく2種類。

**1. 大手クラウド**

AWS・Google Cloud・Microsoft Azure の3社。「ハイパースケーラー」（超大規模なクラウド事業者の総称）と呼ばれる。「手前に置くサービス」も「Cloudflareの上で動かすサービス」も全部持っていて、さらに仮想サーバーやDBなどCloudflareにないものも幅広く提供している。

| 機能           | Cloudflare     | AWS        | Google Cloud  | Azure            |
| -------------- | -------------- | ---------- | ------------- | ---------------- |
| CDN            | Cloudflare CDN | CloudFront | Cloud CDN     | Azure Front Door |
| DNS            | Cloudflare DNS | Route 53   | Cloud DNS     | Azure DNS        |
| WAF            | Cloudflare WAF | AWS WAF    | Cloud Armor   | Azure WAF        |
| ファイル置き場 | R2             | S3         | Cloud Storage | Blob Storage     |

**2. Cloudflareと同じ「手前に置くサービス」が中心の会社**

こちらがCloudflareの直接の競合。

| 会社   | 特徴                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------- |
| Akamai | CDNの最大手で老舗。大企業向けが中心。2022年にLinode（VPS事業者）を買収して、サーバーも提供するようになった    |
| Fastly | CDN + プログラムを動かす仕組み（Compute。CloudflareのWorkersにあたる）+ WAF。Cloudflareに一番近いサービス構成 |

## Cloudflareが目立つ理由

競合は多いのに、Cloudflareの名前が特によく出てくるのは、**DNS・CDN・WAF・DDoS対策を無料プランでまとめて使い始められる**から。

AWSやAkamaiでも同じことはできるが、設定の手間や費用の面で個人・小規模チームには敷居が高い。そのため「手前に置くサービスをまとめて提供している会社」の代表として認識されやすく、個人開発の話題では特によく出てくる。

## 会話では、言い方でどちらの使い方かを見分ける

| 言い方                                                                               | 指しているもの                                 |
| ------------------------------------------------------------------------------------ | ---------------------------------------------- |
| 「Cloudflareを通している」「Cloudflareを挟んでいる」「前段にCloudflareを入れている」 | 自分のサーバーの手前に置く使い方               |
| 「Cloudflareにデプロイした」「Cloudflareで動かしている」                             | Cloudflareの上で動かす使い方（Pages、Workers） |

後者は自分のサーバーを持たない構成ということ。

## 手前に置くサービスを使わない理由

主な理由は3つ。

1. **機密性の高い通信を、第三者に通したくない**: CDNやWAFは、コピーを保存したり攻撃かどうかを判定したりするために、HTTPSで暗号化された通信を一度解いて中身を見る。社内規定や契約で「第三者を経由させてはいけない」と決まっているシステムでは使えない
2. **使うほどじゃない**: 利用者が少ない、利用者がサーバーと同じ地域にいる、社内向けでインターネットに公開していない、などの場合はCDNの利点（負担の軽減、表示の高速化）がどちらも効かない
3. **ドメインを持っていないと使えない**: 手前に置くには、自分のドメインの設定をサービスに向ける必要がある。sslip.io のような借り物のホスト名では使えない

使う場合に受け入れる弱点も2つある。

- **手前のサービスが止まると、自分のサーバーが正常でも使えなくなる**: 手前に置くものが増えるほど「そこが止まったら全部使えなくなる」場所が増える。自分では直せないので、復旧を待つしかない
- **古いコピーが返り続ける**: CSSを更新してデプロイしたのに、CDNが古いコピーを返し続けて利用者に反映されないことがある。コピーの有効期限を決めたり、更新時にコピーを削除したりする管理が必要。設定を間違えて「人によって内容が違うもの」をコピーさせると、他人のページが表示される事故になる
