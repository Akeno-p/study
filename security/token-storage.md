# トークンの保存場所と暗号化

OAuthのアクセストークン・リフレッシュトークンのような「サーバーが元の値を使って外部APIを叩く必要がある秘密のデータ」を、どこに・どう保存するかの整理。

## アプリの設定とユーザーごとの値

| 値                           | 置き場所 | 理由                                               |
| ---------------------------- | -------- | -------------------------------------------------- |
| Client ID / Client Secret    | `.env`   | アプリに1つだけの設定                              |
| Access Token / Refresh Token | DB       | ユーザーごとに違うので、ユーザーのデータとして持つ |

## 保存場所の比較

| 方法                  | 置き場所 | 暗号化の自由度   | ネットワークに流れるか | XSSで盗まれるか        | 備考                                         |
| --------------------- | -------- | ---------------- | ---------------------- | ---------------------- | -------------------------------------------- |
| 自作モデル（DB）      | サーバー | 自由にできる     | 流れない               | 盗まれない             | トークン専用のテーブルを作る                 |
| セッション（DB）      | サーバー | 標準ではできない | 流れない               | 盗まれない             |                                              |
| キャッシュ（Redis等） | サーバー | 実装次第         | 流れない               | 盗まれない             | 高速だが、データが消えることがあるので短期向き |
| Cookie                | ブラウザ | できない         | 毎回流れる             | HttpOnlyなら盗まれない |                                              |
| ローカルストレージ    | ブラウザ | できない         | 流れない               | 盗まれうる             |                                              |

## 暗号化が効く範囲

暗号化には鍵が必要で、鍵はDBとは別の場所（環境変数など）に保管する。どこまで守れるかは侵害の範囲で変わる。

- DBだけが漏洩した場合（SQLインジェクション、バックアップファイルの流出など）→ 鍵がないと復号できないので守れる
- サーバーごと侵害された場合 → 環境変数から鍵も盗まれるため守れない

DB単体の漏洩は現実に起こりうるので、暗号化する価値は十分にある。

## 暗号化のデメリット

| デメリット                                                               | 深刻度                                       |
| ------------------------------------------------------------------------ | -------------------------------------------- |
| 実装の手間                                                               | 一度作れば終わり                             |
| 鍵の管理責任が増える（紛失 = 全ユーザー再認証、漏洩 = 暗号化が無意味に） | 本質的な課題。鍵の置き場所とセットで設計する |
| 鍵のローテーション（定期変更 → 全トークンの再暗号化）の仕組みが必要      | 手間がかかる                                 |
| 使用のたびに復号処理が入る                                               | 個人規模のアプリでは無視できる               |

鍵が漏れても、平文で保存していたのと同じ状態に戻るだけで、暗号化したことで新しい弱点が生まれるわけではない。
