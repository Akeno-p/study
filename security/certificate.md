# 証明書

HTTPS で、接続先のサーバーが本物かを確かめるために使うファイル。「この公開鍵は、このドメインのものだ」と証明機関が保証している。

## 証明書の中身

| 入っている情報           | 例               |
| ------------------------ | ---------------- |
| どのドメインの証明書か   | example.com      |
| サーバーの公開鍵         |                  |
| どの証明機関が発行したか | Let's Encrypt    |
| 有効期限                 | 発行から90日など |
| 証明機関の署名           | 改ざん検知用     |

## 誰が何を持っているか

| 誰           | 持っているもの                                                     |
| ------------ | ------------------------------------------------------------------ |
| サーバー     | 自分のドメインの証明書と秘密鍵                                     |
| 証明機関     | 証明機関自身の秘密鍵。サーバーの証明書に署名するために使う         |
| ブラウザ・OS | 信頼できる証明機関のリスト（証明機関の公開鍵）。最初から入っている |

サーバーの証明書は、接続したときにサーバーから受け取る。

証明書に秘密鍵は入っていない。秘密鍵は別のファイルでサーバーに置く。

```
ssl_certificate     /etc/ssl/example.com.crt;   # 証明書（公開鍵が入っている）
ssl_certificate_key /etc/ssl/example.com.key;   # 秘密鍵
```

nginx の設定の例。`.pfx` や `.p12` のように、証明書と秘密鍵を1つにまとめた形式もある。

## 証明書の発行

証明書は誰でも取れるが、取れるのは自分が持っているドメインの分だけ。証明機関は発行前に「そのドメインの持ち主か」を確認する。

| 誰が                                   | 何の証明書を   | 結果     |
| -------------------------------------- | -------------- | -------- |
| 自分（自分のドメイン所有）             | 自分のドメイン | 取れる   |
| 攻撃者（銀行のドメインは持っていない） | 銀行のドメイン | 取れない |

1つのドメインで複数取れるが、サーバーに置いて使うのは1つ。有効期限が切れる前に取り直す。

### localhost の証明書は発行できない

localhost は全員の PC にあるので、誰のものか保証できない。そのため `https://localhost` は証明書エラーになる。ローカルのテストでは `http://localhost` を使い、本番はドメインを取って証明書を発行する。

## ブラウザがチェックすること

| チェック                       | 確かめ方                                                         |
| ------------------------------ | ---------------------------------------------------------------- |
| 信頼できる証明機関が発行したか | 証明書についている証明機関の署名を、リストの公開鍵で確かめる     |
| ドメイン名が合っているか       | 証明書のドメイン名と、アクセスしようとしているドメイン名を比べる |
| 有効期限が切れていないか       | 証明書の有効期限を見る                                           |
