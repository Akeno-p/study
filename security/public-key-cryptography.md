# 公開鍵暗号

秘密鍵と公開鍵のペアを使う暗号の方式。片方の鍵でしたことを、もう片方の鍵で確かめたり元に戻したりする。公開鍵から秘密鍵を求めることはできない。

RSA、ed25519、ECDSA などの方式があり、計算の仕方がそれぞれ違う。SSH では ed25519 がよく使われる。

## どこで使われているか

| 場面                  | 何のために使うか                                               |
| --------------------- | -------------------------------------------------------------- |
| SSH 接続              | サーバーにログインするとき、本人であることを証明する           |
| HTTPS（TLS）          | 接続先のサイトが本物であることを証明する                       |
| GitHub のコミット署名 | そのコミットを本人が作ったことを証明する                       |
| パスキー              | パスワードを使わずにログインするとき、本人であることを証明する |

## 秘密鍵と公開鍵

| 鍵     | 持つ人     | 扱い                                     |
| ------ | ---------- | ---------------------------------------- |
| 秘密鍵 | 持ち主だけ | 誰にも渡さない。ネットワークにも流さない |
| 公開鍵 | 誰でも     | 誰に見られても問題ない                   |

鍵ペアは `ssh-keygen` などで誰でも作れて、鍵に持ち主の名前は書かれていない。そのため、公開鍵が誰のものかを別の方法で保証する。

| 場面                      | 秘密鍵の置き場所                    | 公開鍵の置き場所                            | 誰のものかの保証                   |
| ------------------------- | ----------------------------------- | ------------------------------------------- | ---------------------------------- |
| SSH（自分の鍵）           | 自分の PC の `~/.ssh/id_ed25519`    | サーバーの `~/.ssh/authorized_keys`、GitHub | 本人がログインして登録する         |
| SSH（サーバーのホスト鍵） | サーバー                            | 自分の PC の `~/.ssh/known_hosts`           | 初めて接続したときに自分で判断する |
| パスキー                  | PC やスマホ（Mac ならキーチェーン） | ログイン先のサービス                        | 本人がログインして登録する         |
| HTTPS                     | サーバー                            | 接続してきた相手に証明書に入れて配る        | 証明機関が証明書で保証する         |

SSH で初めてサーバーに接続したときに出る次の確認が、ホスト鍵の場面。

```
The authenticity of host 'github.com' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no)?
```

## 2つの使い方

| 向き                            | 何になるか                                         |
| ------------------------------- | -------------------------------------------------- |
| 公開鍵で暗号化 → 秘密鍵で復号   | 暗号化。誰でも暗号化できるが、読めるのは持ち主だけ |
| 秘密鍵で署名 → 公開鍵で確かめる | 署名。作れるのは持ち主だけだが、誰でも確かめられる |

## 署名の仕組み

データに秘密鍵で計算をして、その結果をデータに添えること。

```
作る側:      データ → [ハッシュ関数] → ハッシュ値 → [秘密鍵で計算] → 署名

確かめる側:  データ → [ハッシュ関数] → ハッシュ値 ─┐
             署名   → [公開鍵で計算] → 値         ─┴→ 一致するか比べる
```

- 一致すれば、データが書き換えられていないことと、秘密鍵の持ち主が作った署名であることが分かる
- 本人確認に使うときは、相手が毎回ランダムに作るお題に署名する。お題が毎回変わるので、盗み見た署名は使い回せない

これで、秘密鍵を見せずに「秘密鍵を持っていること」を証明できる。
