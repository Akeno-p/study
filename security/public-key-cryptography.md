# 公開鍵暗号

## どこで使われているか

秘密鍵と公開鍵のペアを使う暗号の方式。次のような場面で使われている。

| 場面                  | 何のために使うか                                             |
| --------------------- | ------------------------------------------------------------ |
| SSH 接続              | サーバーにログインするとき、本人であることを証明する         |
| HTTPS（TLS）          | 接続先のサイトが本物であることを証明する（[tls.md](tls.md)） |
| GitHub のコミット署名 | そのコミットを本人が作ったことを証明する                     |

## 秘密鍵と公開鍵

| 鍵     | 置き場所           | 扱い                                         |
| ------ | ------------------ | -------------------------------------------- |
| 秘密鍵 | 自分の PC          | 誰にも渡さない。ネットワークにも流さない     |
| 公開鍵 | 接続先のサーバー   | 誰に見られても問題ない                       |

SSH の場合、秘密鍵は自分の PC の `~/.ssh/id_ed25519`、公開鍵はサーバーの `~/.ssh/authorized_keys` に置く。

### 署名の仕組み

```
秘密鍵 + お題          → [署名用の特殊な計算] → 署名
署名 + お題 + 公開鍵   → [確認用の特殊な計算] → 署名が正しいかどうか
```

- 署名は、秘密鍵がないと作れない
- 公開鍵から、秘密鍵を求めることはできない
- お題は、接続のたびに作られる使い捨てのランダムな値。毎回変わるので、盗み見た署名を使い回せない

これで、**秘密鍵を見せずに「秘密鍵を持っていること」を証明できる**。

## 計算の例

簡単な数字で表すと次のようになる。RSA という方式の例。

|        | 値         |
| ------ | ---------- |
| 秘密鍵 | 2753       |
| 公開鍵 | 3233 と 17 |
| お題   | 65         |

```
署名を作る:  お題 65 を 2753 回掛け算して、3233 で割った余り → 署名 588
確かめる:    署名 588 を 17 回掛け算して、3233 で割った余り  → 65 に戻る → お題と一致するので正しい
```

- 2 つの計算は同じ形で、違うのは「何回掛けるか」だけ。秘密鍵の 2753 と、公開鍵の 17 がその回数にあたる
- 確認用の計算で 65 に戻るのは、17 と 2753 を「戻るペア」になるように作ってあるから
- 65 を 2753 回掛けると数千桁の数になるので、手計算はできない。コンピューターは途中で余りを取りながら計算するので、一瞬で答えが出る

### 鍵の作り方

鍵を作るときは、次の順番で数を決める。ssh-keygen が自動でやっているのはこの作業。

```
1. 秘密の数を 2 つ選ぶ                          61 と 53
2. 2 つを掛け算する                              61 × 53 = 3233          → 公開鍵になる
3. それぞれ 1 引いて掛け算する                  60 × 52 = 3120
4. 3120 と共通の約数を持たない数を選ぶ           17                      → 公開鍵になる
5. 「17 × □ を 3120 で割ると 1 余る」□ を探す    2753                    → 秘密鍵になる
```

5 の答えの確かめ方は次の通り。

```
17 × 2753 = 46801
46801 ÷ 3120 = 15 余り 1
```

- 61 と 53 は、素数（1 とその数自身でしか割り切れない数）の中からランダムに選ぶ。外には出さない
- 5 で見つけた 2753 が、17 と「戻るペア」になる数。5 には 3 の 3120 が必要で、3120 は 61 と 53 がないと出せない

### 公開鍵から秘密鍵がバレない理由

秘密鍵の 2753 を計算するには 61 と 53 が必要。公開されている 3233 から、61 と 53 を探せるかが問題になる。

```
61 × 53 = 3233   ← 掛け算はすぐできる
3233 = ? × ?     ← 元の 2 つを探すのは大変
```

元の 2 つを探すのが大変なので、3233 を公開しても秘密鍵はバレない。

### 実際はもっと複雑

- 実際の鍵は数百桁の数で、計算ももっと複雑。この大きさになると、公開鍵から元の 2 つの数を探す計算は、今のコンピューターでは現実的な時間で終わらない
- SSH でよく使う ed25519 は、RSA とは別の数学を使っている。ただし「秘密鍵と公開鍵のペアを作り、公開鍵から秘密鍵は求められない」という考え方は同じ
