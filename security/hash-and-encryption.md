# ハッシュ化と暗号化

## ハッシュ関数とハッシュ値

```
入力 → [ハッシュ関数] → ハッシュ値
```

- ハッシュ関数: 変換の計算方法。SHA-256 などが代表例
- ハッシュ値: 計算の結果
- 「ハッシュ化する」= ハッシュ関数に入力を通すこと
- ハッシュ値は、入力の大きさに関係なく決まった長さになる（SHA-256 なら16進数で64文字）。入力が1文字でも違うと、まったく別の値になる

パスワードの保存には bcrypt や Argon2 といったパスワード専用のハッシュ関数を使う。

## ハッシュ関数の2つの性質

1. 一方向性: 出力から入力を逆算できない
2. 決定性: 同じ入力なら必ず同じ出力になる

## HMAC

鍵とデータの両方を入力に取るハッシュの仕組み（Hash-based Message Authentication Code）。

普通のハッシュ関数は誰が計算しても同じ結果になるが、HMAC は鍵が違えば結果が変わる。

```
HMAC("鍵A", "hello") → 8a3b2f...
HMAC("鍵B", "hello") → e91c4d...
```

鍵を知らない人は、同じ結果を作れない。

## ハッシュ化と暗号化の違い・使い分け

|              | ハッシュ化 | 暗号化           |
| ------------ | ---------- | ---------------- |
| 元に戻せるか | 戻せない   | 鍵があれば戻せる |
| 鍵の管理     | 不要       | 必要             |

使い分けの基準は「サーバーが元の値を必要とするか」。

| データ               | 保護方法   | 理由                                             |
| -------------------- | ---------- | ------------------------------------------------ |
| パスワード           | ハッシュ化 | 一致するか比較するだけでよく、元の値が不要       |
| アクセストークン     | 暗号化     | 元の値をAPIに送る必要がある                      |
| TOTPのシークレット   | 暗号化     | 元の値でワンタイムパスワードを計算する必要がある |

## パスワード認証の仕組み

```
登録時:     「123」→ ハッシュ化 → 「aseg」→ DBに保存
ログイン時: 「123」→ ハッシュ化 → 「aseg」→ DBの「aseg」と一致 → OK
```

サーバーは元に戻して照合しているのではなく、もう一度同じ計算をして結果が一致するかを見ている（決定性）。

### ハッシュ化はサーバー側で行う

ブラウザからは平文のパスワードが送られ、通信中はHTTPSが守る。

ブラウザ側でハッシュ化してから送ると、ハッシュ値そのものが実質のパスワードになる。傍受した「aseg」をそのまま送ればログインできてしまう。

| 仕組み     | 守っている脅威           |
| ---------- | ------------------------ |
| HTTPS      | 通信中の傍受             |
| ハッシュ化 | DB漏洩時のパスワード流出 |

### DBのハッシュ値が漏れても使い道がない

- 「aseg」から元の「123」は逆算できない（一方向性）
- 「aseg」をそのまま送っても、サーバーがさらにハッシュ化する（「aseg」→「xjfp」）ので一致しない
- 他サービスで使い回しているかもしれない「123」もバレない
