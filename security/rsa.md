# RSA

公開鍵暗号の方式の1つ。簡単な数字で、署名の計算と鍵の作り方を表す。

## 署名の計算

|        | 値         |
| ------ | ---------- |
| 秘密鍵 | 2753       |
| 公開鍵 | 3233 と 17 |
| お題   | 65         |

```
署名を作る:  お題 65 を 2753 回掛け算して、3233 で割った余り → 署名 588
確かめる:    署名 588 を 17 回掛け算して、3233 で割った余り  → 65 に戻る → お題と一致するので正しい
偽の署名:    適当な値 100 を 17 回掛け算して、3233 で割った余り → 1773    → お題と一致しないので偽物
```

- 2つの計算は同じ形で、違うのは何回掛けるかだけ。秘密鍵の 2753 と、公開鍵の 17 がその回数にあたる
- お題 65 は、実際の署名ではハッシュ値にあたる

## 鍵の作り方

ssh-keygen で RSA の鍵を作るときに、自動でやっている作業。

```
1. 秘密の数を 2 つ選ぶ                          61 と 53
2. 2 つを掛け算する                              61 × 53 = 3233          → 公開鍵になる
3. それぞれ 1 引いて掛け算する                  60 × 52 = 3120
4. 3120 と共通の約数を持たない数を選ぶ           17                      → 公開鍵になる
5. 「17 × □ を 3120 で割ると 1 余る」□ を探す    2753                    → 秘密鍵になる
```

- 61 と 53 は、素数（1 とその数自身でしか割り切れない数）の中からランダムに選ぶ。外には出さない
- 5 で見つけた 2753 が、17 と組むと元に戻るペアになる数

## 公開鍵から秘密鍵がバレない理由

2753 を求めるには 3120 が必要で、3120 は 61 と 53 がないと出せない。61 と 53 について公開されているのは、掛け算した 3233 だけ。

```
61 × 53 = 3233   ← 掛け算はすぐできる
3233 = ? × ?     ← 元の 2 つを探すのは大変
```

実際の鍵は数百桁の数なので、元の 2 つを探す計算は今のコンピューターでは現実的な時間で終わらない。
