# TOTPの仕組み

TOTP（Time-based One-Time Password）は、認証アプリに表示される「30秒ごとに切り替わる6桁のコード」のこと。

サーバーと端末が同じシークレット（秘密の値）を持っていて、同じ計算をしているだけ。

## セットアップ

最初のQRコード読み取りは、サーバーが生成したシークレットを端末に渡す操作。

```
サーバー: シークレット「ABCDEF123456」を生成 → QRコードとして表示
スマホ:   読み取ってシークレット「ABCDEF123456」を保存
```

この一度きりの共有以降、シークレットは通信に流れない。

## コード生成

サーバーと端末の両方が、同じ入力で同じ計算をする。

```
HMAC(シークレット, 現在時刻を30秒単位で区切った値) → ハッシュ値 → 決まった手順で6桁を取り出す
```

- HMAC は、鍵を使うハッシュ関数。ここではシークレットが鍵になる
- 30秒経つと時刻の値が変わるので、コードも切り替わる

## 認証の流れ

```
ユーザー: 表示されている「482937」を入力
サーバー: 自分でも同じ計算をする → 「482937」→ 一致するのでOK
```

## なぜ安全なのか

- シークレットを持っていない人は、時刻が分かっても正しい6桁を計算できない
- 6桁と時刻から、シークレットは逆算できない（ハッシュの一方向性）
- 6桁を盗み見られても、30秒後には無効になる
- 総当たりしようにも、30秒の間に100万通りを試す必要がある
