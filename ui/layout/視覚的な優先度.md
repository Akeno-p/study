# 視覚的な優先度

UIでは、すべての要素を同じ強さで目立たせると、どれが重要なのかわかりにくくなる。

そのため、色、背景色、枠線、文字の太さ、サイズ、余白などを使って、要素ごとに優先度をつける。

重要なものほど強く見せる。
補助的なものほど弱く見せる。

## 色には意味と優先度がある

UIで使う色には、大きく分けて2つの役割がある。

- 意味を伝える役割
- 優先度を伝える役割

色はただ見た目をきれいにするためだけではなく、「これは何の操作なのか」「どれが重要なのか」を伝えるためにも使う。

## 色で意味を伝える

色は、要素の意味を伝えるために使える。

例えば、次のような使い分けがある。

- メインカラー: 通常の主要操作
- 赤: 削除、エラー、危険な操作
- グレー: 補助、キャンセル、閉じる、無効状態

登録や保存のように、前に進む操作にはメインカラーを使うことが多い。
削除や退会のように、危険な操作には赤などの警告色を使うことが多い。
閉じるやキャンセルのような補助的な操作には、無彩色を使うことが多い。

このように、色が変わると「意味も変わった」と見えやすい。
だから、意味が同じものに別々の色を使いすぎると、ユーザーが混乱しやすい。

## 色の強さで優先度を伝える

同じ文脈、同じ種類の操作なら、基本的には同じ色を使う。
その中で、色の使い方の強さを変えて優先度を示す。

例えば、同じメインカラーでも次のように強さを変えられる。

- 背景を塗る: 強い
- 枠線だけ色をつける: 中くらい
- 文字だけ色をつける: やや弱い
- グレーにする: 弱い

つまり、色の種類を増やすのではなく、色の占有率や塗りの強さで優先度を出す。

## ボタンの例

例えば、次の3つのボタンがあるとする。

- 閉じる
- 保存
- 確定

この場合、すべてに強い有彩色を使うと、どれが一番重要なのかわかりにくくなる。

閉じる: 無彩色
保存: メインカラーの枠線 + 白背景 + メインカラーの文字
確定: メインカラーの背景 + 白文字

このようにすると、優先度が見た目で伝わる。

- 閉じる: 補助的な操作
- 保存: 途中保存、確定の前段階
- 確定: 最終的に実行してほしい主要操作

ここで大事なのは、保存と確定が同じ流れの中にあるということ。
保存は確定の前段階なので、確定より少し弱く見せるのが自然になる。

## 意味が違う操作では色を分ける

一方で、意味が大きく違う操作なら、別の色を使うことがある。

例えば、登録と削除が並ぶ場合。

登録: メインカラーの塗りボタン
削除: 赤の塗りボタン

この場合、登録は通常の主要操作で、削除は危険な主要操作。
どちらもその場で実行される強い操作なら、両方とも背景色を塗る方が自然な場合がある。

もし削除だけを赤の枠線ボタンにすると、削除が「登録より弱い操作」「補助的な操作」「まだ最終操作ではない操作」のように見えることがある。

つまり、枠線ボタンや白背景のボタンは、見た目上「少し弱い」「前段階」「補助的」という意味を持ちやすい。

ただし、登録と削除のように意味が反対の操作を同じ強さで近くに並べると、誤操作につながることもある。
削除のような危険操作は、位置を離したり、確認ダイアログを出したりして、色以外でも危険性を伝えるとよい。
