# 配色は基本的に3色でまとめよう

配色は **ベースカラー / メインカラー / アクセントカラー** の3色で構成するのが基本。

---

## ベースカラー（画面の約70%）

背景色などに使われる、面積の大きい色。

- 無彩色が使われがちだが、本質は「**低彩度で主張しすぎない色**」。
- 薄く色味をのせることもある（Claude など）。

---

## メインカラー（画面の約20〜25%）

ボタンなどに使われる、ブランドを象徴する色（ブランドカラー）。
扱い方には次の3パターンがある。

### 1. 単色

王道。誠実・安定・分かりやすい。管理画面やコーポレート系に最適。

### 2. 同系色グラデ（青 → 少し濃い青 など）

単色に奥行きをプラス。ほぼ単色感覚で扱える安全策。

### 3. 色相を跨ぐグラデ（青 → 緑 → 赤 など）

画面の2割すべてがグラデだと騒がしくなる。そのため、

- ヘッダーなど**目立つ場所**はグラデにする
- ボタンやリンクは、グラデの中から**代表色を1色選んで単色**で使う

という使い分けがおすすめ。

> 例: [Stripe](https://stripe.com/jp)

### 補足：近年はメインカラーの割合がさらに減っている

「20〜25%」は、PCでWebサイトを見ていた時代の名残（ヘッダーやサイドバーをブランドカラーでベタ塗りしていた）。
近年（2020年代）のSNS・モダンな業務システムでは、メインカラーは **5〜10%以下**まで絞られ、
画面の **90%以上が無彩色（白・黒・グレー）** という構成が主流。

なぜ減ったのか：

1. **主役（中身）を引き立てるため**
   例えばInstagramの主役は運営の色ではなくユーザーの写真。
   器に強い色が25%もあると写真と色が干渉するので、器を無彩色で徹底的に消し、中身を際立たせる。
2. **「どこを押せるか」をより際立たせるため**
   無彩色の中にぽつんと1か所だけ色のボタンがあると、視線が嫌でもそこに向かう。
   面積を絞るほど「ここが押すべき場所（CTA）」の意味が強烈に伝わる。

現代の実質的な比率イメージ：

- ベース（約90%）… 白・黒・各種グレー（背景・枠線・文字・目立たないボタンまでほぼ無彩色）
- メイン（約5〜10%）… 主要な実行ボタン、アクティブなタブの印など
- アクセント・機能カラー … 必要な分だけ

---

## アクセントカラー（画面の約5〜10%）

少量だけど一番目立つ色。色は増やしすぎると意味がわからなくなるので使いすぎ注意。

- 失敗通知・成功通知などとは**別概念**（セマンティックカラー）。
  セマンティックカラーは基本的に一貫して青や赤などで表される。

### アクセントカラーは「どこにあるか」でレイヤーが分かれる

- **トップページ / LP / ブランドサイト** には無いことが多く、
  ベースカラー＋メインカラー（ブランドカラー）のみで構成されがち。

- 一方、**実際のサービス（アプリ内 / 管理画面）** を見ると、
  通知・リンク・メーターを表す決まった色が設定されていることが多く、
  これが実質アクセントとして機能する。

  ※この色は「青＝リンク / 情報」などの慣習に沿った**機能的な色**になりがちで、
  　アクセントカラーとセマンティックカラーの中間に位置する。

---

→ 色は「**ブランドの顔（トップ / ロゴ）**」と「**アプリの中身**」でレイヤーが分かれる。
　アクセントカラーは後者（アプリ内）に存在することが多い。

---

## そもそも3色ルールは「器」に対する話

「3色でまとめる」は、画面の **器（UIの骨格）** に対する原則。

- **器（UIの骨格）** … 背景・ヘッダー・サイドバー・標準ボタンなど。システムの外枠。
  → ここを**3色程度でシンプル**に保つ。
- **中身（データ・状態）** … エラーの赤、ステータスやラベルの色など。
  → 器とは**別のレイヤー**。小さく使う分には色数が多くてもよい。

器をシンプルに保つことで、

- **ノイズが減る**（装飾的な色が少なく、長時間の作業でも目が疲れにくい）
- **中身が際立つ**（器が静かだから、エラーの赤やラベルの色が瞬時に目に入る）

※「3色」と「多くの色」は喧嘩しない。**別のレイヤー**を相手にしているから。
　器は3色でシンプルに、中身は「決めた在庫（パレット）」から選んで秩序を保つ。
