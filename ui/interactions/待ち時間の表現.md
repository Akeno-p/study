# 待ち時間の表現

読み込みや処理に時間がかかるときは、ユーザーに待ち時間のフィードバックを返す必要がある。

何も表示されないまま待たされると、ユーザーは次のように感じやすい。

```md
処理が進んでいるのか
画面が止まっているのか
いつまで待てばいいのか
もう一度操作した方がいいのか
```

そのため、時間がかかる処理では、今処理中であることや、どれくらい進んでいるのかを見せる。

代表的な表現は、主に次の3つ。

- ローディング
- プログレスバー
- スケルトンスクリーン

## ローディング

ローディングは、今処理中であることを伝える表現。

例えば、くるくる回るスピナーや、「読み込み中」といった表示がある。

```md
読み込み中...
保存しています...
送信中...
```

ローディングは、進捗の量まではわからないが、処理中であることを伝えたいときに使う。

短めの処理や、あとどれくらいで終わるかを計算しにくい処理に向いている。

例えば、次のような場合。

- ページの読み込み
- 検索結果の取得
- 保存処理
- 送信処理

ローディングがあると、ユーザーは「今システムが処理している」と理解できる。
逆に、何も表示されないと、押せていないのか、止まっているのか判断しにくい。

## プログレスバー

プログレスバーは、処理がどれくらい進んでいるかを伝える表現。

```text
[======      ] 50%
```

プログレスバーの本質は、少しずつ進んでいることを見せること。

進んでいることが見えると、ユーザーは「待っていれば終わりそう」と判断しやすい。
また、あとどれくらい待てばよさそうかを把握しやすくなる。

プログレスバーは、進捗をある程度計算できる長めの処理に向いている。

例えば、次のような場合。

- ファイルアップロード
- データのインポート
- 動画の変換
- 複数ステップの処理

ただし、進捗がわからない処理に無理にプログレスバーを使うと、かえって不安になりやすい。

例えば、90%で長く止まったり、進んでいるように見えたのに終わらなかったりすると、ユーザーは不信感を持つ。

そのため、プログレスバーは、実際の進み具合をある程度正しく表示できるときに使う。

## スケルトンスクリーン

スケルトンスクリーンは、読み込み後の画面構造を先に見せる表現。

中身のテキストや画像はまだ表示できないが、どこに何が入りそうかを骨組みとして表示する。

例えば、記事一覧なら次のような形になる。

```text
[画像の枠]  [タイトルの線]
          [本文の線]

[画像の枠]  [タイトルの線]
          [本文の線]
```

スピナーだけの場合、ユーザーには「何かを待っている」ことしかわからない。
一方で、スケルトンスクリーンなら、読み込み後の画面の形を先に把握できる。

```md
ここに画像が入る
ここにタイトルが入る
ここに説明文が入る
この形の一覧が表示される
```

そのため、画面全体が止まっている感じを減らせる。
また、中央に毎回ローディングを出すよりも、一覧やカードの画面に馴染みやすい。

スケルトンスクリーンは、読み込み後の形が予測できる画面に向いている。

例えば、次のような場合。

- 記事一覧
- 商品一覧
- ユーザー一覧
- 通知一覧
- カード型のダッシュボード

逆に、読み込み後に何が表示されるか予測しにくい場合や、完了後にまったく違う画面へ進む場合は、スケルトンスクリーンよりローディングの方がわかりやすい。

## 使い分け

待ち時間の表現は、処理の長さや進捗がわかるかどうかで使い分ける。

```md
ローディング:
短めの処理や、進捗がわからない処理に使う。
「今処理中である」ことを伝える。

プログレスバー:
長めの処理で、進捗を計算できる場合に使う。
「どれくらい進んでいるか」を伝える。

スケルトンスクリーン:
一覧やカードなど、読み込み後の画面構造が予測できる場合に使う。
「どこに何が表示されるか」を先に見せる。
```

短い待ち時間なら、ローディングで十分なことが多い。

長い待ち時間で、進捗がわかるならプログレスバーが向いている。

一覧やカードの読み込みのように、画面構造が決まっている場合は、スケルトンスクリーンが向いている。

## 何をしているのかも伝える

待ち時間の表現では、ただ動きを出すだけでなく、何の処理をしているのかも伝えるとわかりやすい。

```md
読み込み中です
保存しています
画像をアップロードしています
データを取得しています
```

何のために待っているのかがわかると、ユーザーは状況を理解しやすい。

特に、時間がかかる処理では、「何をしているのか」を言葉で補うと安心しやすい。

## まとめ

読み込みや処理に時間がかかるときは、待ち時間のフィードバックを返す。

何も表示されないと、ユーザーは処理が進んでいるのか、止まっているのか、いつまで待てばよいのかを判断しにくい。

短めの処理や進捗がわからない処理には、ローディングを使う。

長めの処理で進捗を計算できる場合は、プログレスバーを使う。
プログレスバーは、少しずつ進んでいることと、あとどれくらい待てばよさそうかを伝えるためのもの。

一覧やカードなど、読み込み後の画面構造が予測できる場合は、スケルトンスクリーンを使う。
スケルトンスクリーンは、画面の骨組みを先に見せることで、待っている感覚を軽くする。

大事なのは、ローディング、プログレスバー、スケルトンスクリーンを状況に合わせて選ぶこと。
