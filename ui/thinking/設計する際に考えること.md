# 設計する際に何を意識するのか？ 何を考えるのか？

## 1.　誰のために作るのかを明確にする

まず最初に考えるのは「誰が使うのか？」ということ。

- この人はどんな生活をしていて、どんな場面でこのサービスに触れるのか？
- この人はITやスマホにどれくらい慣れているのか？
- この人がこのサービスを使って、なんて言ってくれたら成功なのか？

こうした問いを通じて、使う人の姿を具体的にしていき、**ニッチ層を直撃するデザイン**を考える。

### 🎯 なぜターゲットを絞るのか

「みんなに使ってほしい」「どんな人にもいいと感じてほしい」とは思うが、デザインの判断にはトレードオフがある。

▼ 例

- 文字を大きくすれば高齢者には見やすいが、若い世代には情報量が少なく感じる
- 専門用語を使えば慣れた人には効率的だが、初めての人には意味がわからない
- 操作のステップを細かく分ければ慎重な人には安心だが、慣れた人にはまどろっこしい

全員にとって最適なものを目指すと、すべてのトレードオフで中途半端な妥協をすることになる。
結果として、誰にとっても「まあまあ」だけど、誰にも「これがいい」と思われないものになりやすい。

ターゲットを絞ることで、「この人にとって最高のもの」を目指した判断ができるようになる。

### 🔀 ターゲットを絞ることと、排除することは違う

「20代の社会人女性向けに最適化する」は、他の人が使えないようにするという意味ではない。

あくまで、迷ったときの判断基準を持つということ。
文字サイズ、言葉遣い、操作の流れなどで「どちらにしよう？」と迷ったとき、ターゲットが明確なら判断しやすくなる。

### ♿ アクセシビリティはターゲットとは別の話

色覚多様性への配慮や、十分なコントラストの確保、スクリーンリーダーへの対応など。
これらは「ターゲットを広げる」ではなく「基本品質」にあたる。

ターゲットを絞ったとしても、アクセシビリティは確保するのが前提。

### 🌱 大きなサービスも最初はターゲットを絞っていた

今では幅広い世代に使われているサービスでも、最初から全員を狙っていたわけではない。

例えば、LINEも最初は日本の若い世代向けのメッセージアプリとして広まった。
まず特定の層に深く刺さるものを作り、そこから徐々に広がっていった。

「まず誰か一人に刺さるものを作る」が、結果的に多くの人に届くものにつながることがある。

## 補足:利用者の欲望を理解する

ターゲットを決めたら、次はその人の**本質的な欲望**を掘る。

「若者が使うから今どきなかっこいいUI」では浅い。
なぜかっこよくしたいのか？ その人は何を求めているのか？ まで考える。

### 🧊 表の欲望と裏の欲望

欲望には2つの層がある。

- **表の欲望（機能的）**: 良い商品を見つけたい、スペックを比較したい、早く買いたい
- **裏の欲望（感情的）**: 周りにすごいと思われたい、自分らしくいたい、特別な存在でいたい

表の欲望だけ満たしても「便利だね」で終わる。
裏の欲望まで届くと「ここじゃなきゃダメ」「このサービスが好き」になる。

デザインに差が出るのは、この裏の欲望をどれだけ理解しているかによる。

### 💡 具体例：エンジニア向けガジェット販売サイト

ターゲットが20代のエンジニア男性だとする。

この層の裏の欲望を考えてみる：

- 周りからPCを使いこなしててかっこいいと思われたい
- そんな難しいことができるなんてすごいと尊敬されたい
- ちょっと周りとは違うやつと思われたい

この欲望がわかると、デザインの方向性が見えてくる。

例えば、黒背景でCLIベースのUIにして、注文も `/order` のようなコマンドからできるようにする。
誰もが使えるわけじゃないけど、扱えていたらかっこいい。異端感がある。

「ここで買い物してる俺かっけー」と思わせる。
これが裏の欲望に届いたデザイン。

### 🐙 身近な例：Claude Code

Claude Codeも同じ構造で作られている気がする。

- ターミナルで動くCLIツール → GUIではなくCLIを使いこなしている自分、というかっこよさ
- マスコットがアスキーアートのタコ → 「わかるやつにはわかる」内輪感、ギーク感
- あえて洗練しすぎないデザイン → 開発者文化へのリスペクト、「自分たちの道具」感

もしこれが洗練されたGUIアプリで、きれいなイラストのマスコットだったら、機能は同じでも「自分たち向けの道具だ」という感覚は薄れる。

「CLIでAIを使いこなしてる俺かっけー」が成り立っている。
裏の欲望を理解して、デザインに落とし込んでいる好例。

## 2. どこまで作り込むかを決める

作り込みは無限にできる。
ただ無限にやっていたら時間がなくなる。
なので「どこまでやるか？」「どこまでやったら価値が生まれるのか？」というゴールを先に決めておく必要がある。

### 📏 最低ライン：ユーザーの欲求を満たせるレベル

どんな状況でも、ユーザーが求めていることをストレスなく達成できるレベルは必要。
競合がいなくても、操作が難しすぎたり、わかりにくすぎたり、ダサすぎると、ユーザーは「使わない」という選択をする。

えきねっとが良い例で、競合がいないからUXが悪くても成り立っていた。
新幹線の切符はえきねっとからしか買えないし、他の新幹線に乗るという選択肢もない。

でも実際には「こんなにわかりにくいならみどりの窓口で買う」という人が多く、結局リニューアルされた。
競合がいなくても、ユーザーが別の手段に逃げられる場合は、UXの質が求められる。

### 🔍 競合を見て基準を知る

最低ラインを超えたうえで、どこまで磨くかを判断するときに大事なのが競合を見ること。

- 競合のレベルが高いなら、それと同等以上でないとユーザーに選んでもらえない
- 競合がいない、または弱いなら、最低ラインを超えていれば過度に凝る必要はない

競合を見ることで「このくらいあれば戦える」「ここは差をつけられる」という基準が見えてくる。

先ほどのえきねっとの例につながるが、改善はされたけどオシャレではないし、超わかりやすいかと言ったらそんなこともない。
だけど競合がいないので成り立ってる。

## 3. 指針を決めておく

実際に作り始めると、判断に迷う場面がたくさん出てくる。

▼ 周りから言われること

- エンジニアから「それは実装コストが高いから難しい」
- 上司から「もっとここのテキスト大きくした方が見やすくない？」

▼ 一人で悩むこと

- これ実際作るのめんどくさいな...
- これやるってなったら結構重くなるな...
- 派手でオシャレなUIか、シンプルで見やすいUIか、どっちがいいかな...

こういうとき、その場その場で判断していると、方向性がブレていく。
なので、あらかじめ**何を優先して、何を優先しないか**の指針を決めておく。

### 📐 指針の例

> 見やすさよりはデザイン性を優先します。
> 軽さよりもデザイン性を優先します。
> ただし、実害が出るレベルにはしません。重くてサイトが落ちるとかはダメ。

こういう形で、優先順位と許容範囲をセットで決めておくと、迷ったときの判断基準になる。

### 🔗 指針はターゲットから決める

指針は好みやなんとなくで決めるのではなく、セクション1で決めたターゲットとつながっている。

例えば、ターゲットが「かっこいいと思われたい20代エンジニア」なら、デザイン性を優先するのは理にかなっている。

ただ、もしターゲットが「ITに不慣れな高齢者」なら、同じ指針にはならない。
見やすさやわかりやすさが最優先になるはず。
