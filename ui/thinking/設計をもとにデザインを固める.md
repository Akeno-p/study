# 設計をもとにデザインを固める方法について

## やること：デザインシステムを作る

一番最初にデザインのパターン（ルール）を作る。

- テキストのフォントはどれを使うか
- 使う色はどれか
- ステータスを表す色は何色か
- ステータスの状態を何で表現するか

など、デザインの土台になるルールを先に決める。

これらを決めておくことで**一貫性**が生まれる。
一貫性は非常に大事。理由は次のとおり。

1. **見栄えがいい**
2. **ブランドとして浸透する** — デザインが定まることで、サービスの世界観がブランドとして伝わる
3. **使いやすい** — いつも同じ場所にボタンがある、成功を表す色はいつも同じ、と一貫していると迷わず使える

> 補足：3番目は特に大事。
> 頻繁にUIをアップデートするサービスは、オシャレで見やすくて使いやすかったとしても「使いづらい」と感じられてしまうことがある。
> それは一貫性がないから。なので一貫性は必ず持たせる。

※ デザインシステムの中でコンポーネントをどう構造化するかは [アトミックデザイン](../design-system/アトミックデザイン.md) を参照。

---

## 全体の流れ

1. 設計で決めた方針をもとに、叩き台となる `design.md` を作る
2. AI（Claude Design）でプロトタイプを形にする
3. デザイン段階でひたすら詰める
4. 固まったらexport / Claude Codeに共有して実装へ

---

## 1. 叩き台になる design.md を作成する

[設計する際に考えること](./設計する際に考えること.md) で考えた内容（ターゲット・指針・デザインシステムの方針）をもとに、`design.md` を作成する。

このファイルが、これ以降AIに指示を出すときの土台になる。

## 2. AIを使ってデザインを形にしていく

`design.md` をもとに、AIでいきなりプロトタイプを作る。

昔はFigmaなどを使ってデザインしていたが、今はAIを使って作る方が早い。
ただし、この段階では**コードは書かない**。

Claude CodeやCodexでいきなり実装させても作ることはできるが、デザインだけを出力する専用のAIと比べると時間がかかるし、トークン使用量も馬鹿にならない。

それに、CLIベースでデザインの指示を出すのは普通に少し難しい。
できないことはないが、デザインが固まり切っていない状態でそれをやるのは結構きつい。

具体的には、**Claude Design** で design system を選択して作っていく。

## 3. Claude Design でひたすら詰めていく

バックエンドを実装してからデザインを変更するのは大変。
なので、Claude Designの時点でひたすら詰めておく。

詰め終わったら、実際にexportしたりClaude Codeに共有したりして、そこからバックエンド側の作成まで進めていくイメージ。
