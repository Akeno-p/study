# 現在地の示し方

階層構造があるページでは、ユーザーが「今どこにいるのか」を理解できるようにする必要がある。

現在地がわからないと、ユーザーは次のように迷いやすくなる。

- 今どのカテゴリの中にいるのかわからない
- ひとつ上の階層に戻る方法がわからない
- 同じ階層の別ページへ移動しにくい
- 自分が目的の場所にいるのか判断しにくい

現在地を示す代表的な方法は、主に次の2つ。

- カレント表記
- パンくずリスト

## カレント表記

カレント表記とは、ナビゲーションやサイドバーの中で、今見ているページや項目を強調する方法。

例えば、サイドバーで今いるページだけ背景色を変えたり、文字を太くしたりする。

```text
トップページ
商品紹介  ← 現在地として強調
採用情報
お問い合わせ
```

カレント表記は、ナビゲーション内で「今どの項目を見ているか」を示すのに向いている。

特に、次のような場合に使いやすい。

- 階層が浅い
- サイドバーやタブがある
- 画面数がそこまで多くない
- アプリ型UIや管理画面
- 同じ階層のページを行き来することが多い

例えば管理画面では、サイドバーのカレント表記だけで現在地が十分わかることが多い。

```text
ダッシュボード
商品管理
  商品一覧  ← 現在地として強調
  カテゴリ管理
注文管理
ユーザー管理
```

## カレント状態とホバー状態は分ける

カレント状態とホバー状態は、意味が違う。

カレント状態は、今そのページを見ていることを示す継続的な状態。
ホバー状態は、今マウスカーソルが乗っていることを示す一時的な状態。

この2つを同じ見た目にすると、現在地とホバー中の項目が混ざってわかりにくくなる。

そのため、カレント表記を使う場合は、ホバー状態と別の表現にする。

## パンくずリスト

パンくずリストとは、今いるページまでの階層の道筋を表示する方法。

```text
ホーム > 商品一覧 > 文房具 > ペン > 商品A
```

パンくずリストは、「今いるページが階層のどこにあるか」を示すのに向いている。
また、上の階層へ戻る導線にもなる。

そのため、パンくずリストは基本的にクリックできるようにする。
現在のページ以外の階層は、上のページへ戻るためのリンクにする。

```text
ホーム > 商品 > 文房具 > ペン > 商品A
```

この場合は、次のように考える。

- ホーム: リンク
- 商品: リンク
- 文房具: リンク
- ペン: リンク
- 商品A: 現在地なのでリンクなし

現在のページは、押しても同じページに戻るだけなので、表示だけでよい。

特に、次のような場合に使いやすい。

- 階層が深い
- 詳細ページが大量にある
- ナビにすべてのページを表示できない
- 上のカテゴリへ戻る導線が重要
- ECサイト、ドキュメントサイト、大規模メディアなど

例えばECサイトの商品詳細ページでは、ナビゲーションにすべての商品を表示するのは現実的ではない。

そのため、細かい現在地はパンくずリストで示す。

```text
ホーム > 文房具 > ペン > ボールペン > 商品A
```

このようにすると、ユーザーは商品Aがどのカテゴリにあるのか理解しやすい。
また、「ペン」や「文房具」の階層へ戻りやすくなる。

## 基本は両方出さなくていい

カレント表記とパンくずリストは、どちらも現在地を示すためのもの。

そのため、両方を必ず出す必要はない。
むしろ、両方出すと情報が重複して、画面がごちゃつくことがある。

基本は、必要最小限で考える。

```md
カレント表記だけで現在地が十分わかるなら、パンくずリストは出さなくてもよい。
```

例えば、階層が浅く、サイドバーやタブで現在地が明確な画面なら、カレント表記だけで十分なことが多い。

```text
サイドバー
- ダッシュボード
- 商品管理
- 注文管理  ← 現在地として強調
- ユーザー管理
```

この状態でさらに、

```text
ホーム > 注文管理
```

を毎回表示すると、少し重く感じることがある。

## パンくずリストだけでよい場合

パンくずリストだけで現在地を示す場合もある。

特に、ナビゲーションに細かいページを出しきれない場合。

例えば、ECの商品詳細、記事詳細、求人詳細、物件詳細など。

```text
ホーム > 商品 > 文房具 > ペン > 商品A
```

この場合、グローバルナビには大きなカテゴリだけが表示されていて、商品Aのような細かいページまでは表示されないことが多い。

```text
グローバルナビ
商品 / サポート / 会社情報
```

このような場合は、カレント表記よりもパンくずリストの方が細かい現在地を示しやすい。

## 使い分け

カレント表記とパンくずリストは、役割が少し違う。

```md
カレント表記:
ナビゲーションの中で、今どの項目を見ているかを示す。

パンくずリスト:
階層の道筋と、上の階層へ戻る導線を示す。
```

使い分けるときは、次のように考える。

- ナビで現在地を示せるなら、カレント表記
- ナビに出しきれない細かい階層を示したいなら、パンくずリスト
- 階層が浅くシンプルなら、カレント表記だけでよい
- 階層が深く、上の階層へ戻る導線が重要なら、パンくずリストを使う
- 両方必要な場合もあるが、情報が重複しないか注意する

## まとめ

階層構造があるページでは、ユーザーが現在地を理解できるようにする必要がある。

代表的な方法は、カレント表記とパンくずリスト。

ただし、両方を必ず出す必要はない。
基本は、必要最小限で考える。

シンプルな構造なら、カレント表記だけで十分なことが多い。
ナビに出しきれない細かい階層がある場合は、パンくずリストが役に立つ。

カレント表記を使う場合は、ホバー状態と同じ見た目にしない。
カレント状態は現在地、ホバー状態は一時的な操作反応なので、別の表現にする。

パンくずリストを使う場合は、現在ページ以外の階層をクリックできるようにして、上の階層へ戻れる導線にする。

大事なのは、パンくずリストを出すこと自体ではなく、ユーザーが「今どこにいるのか」「どこへ戻れるのか」を迷わず理解できること。
