# コマンドたち

## 📊早見表

| コマンド   | 内容                                         |
| ---------- | -------------------------------------------- |
| `/usage`   | 使用量と上限までどのくらいかが見える。       |
| `/status`  | バージョンやモデル、ログイン情報を確認する。 |
| `/model`   | モデルを変更する。                           |
| `/clear`   | 会話履歴を全部消してまっさらにする。         |
| `/compact` | 会話を要約して文脈を保ったまま圧縮する。     |
| `/context` | コンテキストの使用状況を視覚的に確認する。   |
| `/btw`     | 会話履歴に残さずサッと質問できるサイドバー。 |

## /usage

使用量と上限までどのくらいかが見える

## /status

claude codeの情報(バージョン情報やmodelやログイン情報など)が確認できる

## /model

モデルを変更する
選択肢にないモデルを指定したい時は下記のようにしたら指定できる

```text
/model claude-opus-4-5
```

## /clear

### 使用方法

コンテキスト(会話履歴)をクリアする

コンテキストが大きくなることのデメリット:

- コストが増える: Claude APIは入力トークン数に応じて課金されるため、会話が長くなるほどトークン消費が加速する
- 応答が遅くなる: 処理するテキスト量が増えるため、レスポンスが遅くなる
- 古い情報に引きずられる: 会話の序盤で間違った方向に進んだ場合、修正しても過去の文脈に引っ張られることがある
- コンテキストウィンドウの上限: モデルの処理上限に近づくと、古い会話が自動で要約・圧縮され、重要な情報が落ちる可能性がある

いつ /clear すると良いか:

- 話題が完全に変わるとき
- 試行錯誤が長引いて文脈が散らかったとき
- 応答の質が落ちてきたと感じたとき
- 同じ問題で2回以上修正を繰り返しているとき

## /compact

### 使用方法

会話を要約してコンテキストを軽くする（文脈は保持される）

```
/compact                              # 自動で要約
/compact API変更の部分だけ残して       # 残したい内容を指示できる
```

/clear との違い:

- /clear: 会話を全部消してまっさらにする
- /compact: 会話を要約して残す。文脈を保ったまま軽くなる

いつ /compact すると良いか:

- 同じ話題を続けたいけどコンテキストが重くなってきたとき
- 次の大きなタスクに移る前に、必要な文脈だけ残したいとき

フォーカス指示を添えると、自動の要約よりも残したい文脈をコントロールできるので、公式もこちらを推奨している

## /context

コンテキスト（会話履歴）の使用状況を確認できる

### 使用方法

```
/context       # 基本的な使用状況の表示
/context all   # 詳細な内訳も含めて表示
```

表示される情報:

- カラーグリッド: 現在のコンテキスト使用状況を色付きのグリッドで視覚化する
- 最適化の提案: MCPサーバーやファイルアクセスなど、コンテキストが重いツールの最適化案を表示する
- 詳細な内訳: `all` オプションを使うと、項目ごとの内訳を展開して確認できる

コンテキストには会話テキスト以外にも、システムプロンプト（CLAUDE.mdなど）、ツール定義（Bash、Read、Editなど）、MCPサーバー情報、ツール実行結果など目に見えない部分も含まれている。/context を使うとこれらの内訳を把握できる

いつ /context すると良いか:

- 長時間の会話の途中で、コンテキストウィンドウの残り容量を確認したいとき
- 大規模なプロジェクト作業で、メモリ肥大化の原因を特定したいとき
- /clear や /compact をする前に、現状を把握したいとき

### コンテキスト管理の考え方

公式の推奨は容量の数値よりも「会話の質」で判断すること。
ただ目安として下記の表ぐらい。(AIが書いた内容なので正しくないかも)

| Free space | 状態         | やること                          |
| ---------- | ------------ | --------------------------------- |
| 50%以上    | 余裕あり     | そのまま続けてOK                  |
| 30〜50%    | そろそろ意識 | 話題が変わるタイミングで /compact |
| 15〜30%    | 要注意       | /compact した方がいい             |
| 15%以下    | 危険         | /clear を検討                     |

## /btw

コンテキストに残さずにその場限りの質問できる機能。claudeが作業中でも割り込みで使える。

ちなみにbtwはby the way(ところで)の略

### 使用方法

```
/btw あの設定ファイルの名前なんだっけ？
```

### 特徴

- 会話履歴に残らない: 質問と回答はオーバーレイに表示されるだけで、メインの会話には一切入らない
- claudeの作業中でも使える: メインの処理を中断せずに独立して実行される
- ツールアクセスなし: 今の会話コンテキストの中にある情報だけで回答する。ファイルを読んだりコマンドを実行したりはできない
- 1回きりの回答: オーバーレイ内でのフォローアップはできない。続きが必要なら `f` キーで新しいセッションにフォークできる
- 低コスト: 元々の会話のプロンプトキャッシュを再利用するからコストが低い

### オーバーレイのキー操作

| キー                      | 動作                                                   |
| ------------------------- | ------------------------------------------------------ |
| `Space` / `Enter` / `Esc` | 回答を閉じてプロンプトに戻る                           |
| `c`                       | 回答をMarkdownとしてクリップボードにコピー             |
| `f`                       | 新しいセッションにフォーク（ツールアクセス付きで続行） |
| `x`                       | 過去の /btw のやり取り一覧をクリア                     |
