# ワークフロー系のコマンドたち

## /loop

繰り返し実行してほしいプロンプトを登録して、間隔は自分で決めるかClaudeに任せるかを選べるコマンド

### 使用方法

```
/loop 5m デプロイが終わったか確認して       # 5分ごとに実行
/loop デプロイが終わったか確認して           # 間隔はClaudeが自動で判断
/loop 20m /review-pr 1234                    # 別のコマンドを繰り返すこともできる
```

間隔の単位: `s`（秒）、`m`（分）、`h`（時間）、`d`（日）

### 間隔を省略した場合（自動ペース）

間隔を書かずにプロンプトだけ渡すと、Claudeが状況に応じて待ち時間を自動で判断する

- 動きがありそうなとき → 短い間隔（数分）でこまめに確認
- 静かなとき → 長い間隔（最大1時間）でゆったり確認

### 向いている使い方

「変化を待って、それに反応する」系の作業。簡単だけど少し判断が必要なタスクに向いている

- デプロイやビルドの完了待ち
- メールを見て緊急性が高い場合のみSlackで通知
- PRのCIやレビューコメントの監視

### 注意点

- セッションが開いていてPCが起動している間だけ動く（PCを閉じると止まる）
- 間隔ごとにトークンを消費するので、空振りが多いとコストがかかる
- 止めたいときは `Esc` キー
- 作成から7日後に自動終了

### 仕事で使う場合の線引き

個人プロジェクトなどなら話は別だが、
仕事で他人が関わる場合、AIの出力をそのまま成果物として出すのは問題が多いと感じた。

- 確認作業という自分の仕事を他人に押し付けることになる
- 成果物に対して自分が責任を持てない
- 誰も説明できないコードが溜まっていく（理解負債の蓄積）

ネットでは「完全自動化！」という意見もあるし、自分でコードを確認しなくても問題がない方法があるのかもしれない。なので、そういった意見を間違っていると言いたいわけではなく、少なくとも今の自分にはそれはできないので、仕事などで使うならこのスタンスでいこうと思った。

👮 **やるとしてもここまで:**

- レビューコメントの読み取り・整理
- worktreeを切って修正案を作る
- 開発サーバー起動＋Playwrightなどで修正案の動作確認
- Notionに修正案をまとめ → Slackで自分宛に通知

それをみて、本当にその修正でいいのかの判断してPRを出すのは自分

AIには「調べる・準備する・確認の補助をする」までをやらせる。「理解する・判断する・成果物として世に出す」は自分でやる。
