# gitについて

gitの色々な知識をまとめたやつ

---

## ⭐️ ブランチは「コミットへのポインタ」でしかない

ブランチは、フォルダのコピーでも、作業スペースでもない。
**ある1つのコミットを指し示す「付箋」**のようなもの。

```
main     → コミットC
feature  → コミットE
```

ブランチを切り替えるというのは、この「今どの付箋を見ているか」を変えることでしかない。
だから**ブランチの作成は一瞬で終わる**（付箋を1枚貼るだけだから）。

## ⭐️ 作業ツリー（working tree）はブランチに属さない

**ディスク上のファイルは、この世に1セットしか存在しない。**
ブランチごとにファイルのコピーが存在するわけではない。

| もの                           | ブランチに属するか                |
| ------------------------------ | --------------------------------- |
| コミットされた履歴             | ✅ 属する                         |
| 作業ツリー（編集中のファイル） | ❌ **属さない。全ブランチで共有** |

つまり、**まだコミットしていない変更は「どのブランチのものでもない」**。
だからブランチを切り替えても、その場に残り続ける。

### 結果として何が言えるか

- **ブランチを切り忘れて作業しても、後から切ればいい**
  → `git switch -c ブランチ名` すれば、未コミットの変更ごと新ブランチに移る
  → 「最初から切っていた場合」と、最終的なコミット履歴は完全に同一になる
- 未コミットの変更は「運ばれている」のではなく、**最初から動いていない**

---

## ⭐️ ブランチ切り替えが拒否される条件

「未コミットの変更があるとブランチを移動できない」のではなく、切り替えによって、未コミットの変更が上書きされて消えるのを防いでいる。

### 3つのケースで検証した結果

| ケース | 状況                                                       | 結果                                          |
| ------ | ---------------------------------------------------------- | --------------------------------------------- |
| 1      | untracked な新規ファイルがある                             | ✅ **切り替え成功**（ファイルはそのまま残る） |
| 2      | 追跡中のファイルを編集中。切り替え先でも**その内容が同じ** | ✅ **切り替え成功**（編集を保持したまま移動） |
| 3      | 切り替え先で**同じファイルの内容が違う**                   | ❌ **拒否される**                             |

### なぜケース3だけ拒否されるのか

Gitは切り替えのとき、こう考えている。

```
今のブランチのHEAD :  login.html = "A"
切り替え先のHEAD   :  login.html = "B"   ← 違う
```

→ 切り替えるには、ディスク上の login.html を "B" に書き換えなければならないが、未コミットの編集が乗っていることになり、書き換えたらその編集が消えるため、とめる

**gitは復元できない処理を暗黙的に行うことを嫌っている。**

---

## 🔧 Gitは「差分」ではなく「スナップショット」を保存している

Gitは "AをBに変えた" という差分を積み上げて保存しているわけではなく、その時点の**ファイルの中身まるごと**を持っている。

```
コミット1 : login.html の中身は "A"（丸ごと）
コミット2 : login.html の中身は "B"（丸ごと）
```

`git diff` で見える差分は、2つのスナップショットを**表示するときに計算している**だけ。
