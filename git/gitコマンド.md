# gitのコマンドについて

## 早見表

| コマンド                              | 説明                                       |
| ------------------------------------- | ------------------------------------------ |
| `git init`                            | 現在のディレクトリをGitで管理し始める      |
| `git clone URL`                       | リモートのリポジトリをローカルにコピーする |
| `git add パス`                        | 指定したファイルをステージング             |
| `git add .`                           | 今いるディレクトリ以下の変更をステージング |
| `git add -A`                          | プロジェクト全体の変更をステージング       |
| `git commit -m "メッセージ"`          | ステージングした変更を履歴として記録       |
| `git commit --amend -m "メッセージ"`  | 直前のコミットを上書き修正                 |
| `git reset --soft HEAD~1`             | コミットを取り消す（変更は残る）           |
| `git reset --hard HEAD~1`             | コミットも変更もすべて消す                 |
| `git remote add origin URL`           | リモートの接続先を登録する                 |
| `git push`                            | コミットをリモートに送る                   |
| `git push --set-upstream origin main` | 初回push（ブランチの紐付け）               |
| `git pull`                            | リモートの変更をローカルに反映             |
| `git fetch origin`                    | リモートの最新情報を取得だけする           |
| `git merge ブランチ名`                | 他のブランチの変更を取り込む               |
| `git status`                          | 作業状態を一覧で確認                       |
| `git diff`                            | 変更された箇所を差分で表示                 |
| `git log`                             | コミット履歴を確認                         |
| `git log -p`                          | コミット履歴を変更内容付きで確認           |
| `git branch`                          | ブランチを一覧表示                         |
| `git branch ブランチ名`               | 新しいブランチを作成                       |
| `git branch -d ブランチ名`            | マージ済みのブランチを削除                 |
| `git branch -D ブランチ名`            | ブランチを強制削除                         |
| `git branch -m 新しい名前`            | ブランチ名を変更                           |
| `git branch -a`                       | リモート含めて一覧表示                     |
| `git switch ブランチ名`               | ブランチを切り替える                       |
| `git switch -c 新しいブランチ名`      | ブランチの作成と切り替えを同時にやる       |
| `git restore ファイル`                | 編集を捨てて、コミット時の状態に戻す       |
| `git restore --staged ファイル`       | ステージングだけを取り消す（編集は残る）   |
| `git log --graph --oneline`           | 履歴を枝分かれの形で1行ずつ表示            |
| `git stash`                           | 変更を一時的に退避する                     |
| `git stash push -m "メッセージ"`      | メッセージ付きで退避する                   |
| `git stash pop`                       | 退避した変更を元に戻す                     |
| `git stash list`                      | 退避中の変更を一覧表示                     |
| `git stash apply`                     | 退避した変更を元に戻す（スタッシュは残る） |
| `git stash drop`                      | 特定のスタッシュを削除                     |
| `git worktree add パス ブランチ名`    | 別の作業ディレクトリを作成                 |
| `git worktree list`                   | worktreeの一覧を表示                       |
| `git worktree remove パス`            | worktreeを削除                             |

---

## ⭐️ git init

一番最初に使うコマンド。
現在のディレクトリに `.git` という隠しフォルダを作成し、そのフォルダをGitで管理し始める。
`.git` フォルダの中に、変更履歴やブランチ情報などバージョン管理に必要な情報がすべて保存される。
既存のプロジェクトでも、空のフォルダでも実行できる。

## ⭐️ git clone URL

リモートのリポジトリを**ローカルにコピーする**コマンド。
`git init` + `git remote add` + `git pull` を一発でやってくれる。
既にあるリポジトリに新しく参加するときに使う。

```bash
git clone https://github.com/ユーザー名/リポジトリ名.git
```

## ⭐️ git add

コミットする前に記録対象と指定するコマンド。この操作を**ステージング**と言う。

| コマンド       | 対象範囲                                         |
| -------------- | ------------------------------------------------ |
| `git add パス` | 指定したファイルだけをステージング               |
| `git add .`    | 今いるディレクトリ以下の変更をすべてステージング |
| `git add -A`   | プロジェクト全体の変更をすべてステージング       |

`git add .` と `git add -A` の違いは、プロジェクトのルートにいるときは同じ動きになるが、サブディレクトリにいるときは `git add .` はそのディレクトリ以下のみ、`git add -A` はプロジェクト全体が対象になる。

## ⭐️ git commit

ステージングした変更を**履歴として記録する**コマンド。
コミットする際は、何を変更したのかわかるようにメッセージをつける。

```bash
git commit -m "コミットメッセージ"
```

メッセージは「何をしたか」を簡潔に書くのがポイント。（例：`"ログイン機能を追加"`, `"READMEを修正"`）

## 🔧 git commit --amend

直前のコミットを**上書き修正**するコマンド。

| 用途                   | コマンド                                        |
| ---------------------- | ----------------------------------------------- |
| メッセージを修正したい | `git commit --amend -m "正しいメッセージ"`      |
| ファイルを追加し忘れた | `git add 忘れたファイル` → `git commit --amend` |

まだ `git push` していないコミットにだけ使うこと。pushした後に使うと履歴が崩れて面倒なことになる。

## 🔧 git reset

コミット自体を**取り消す**コマンド。

| コマンド                  | 動作                                               |
| ------------------------- | -------------------------------------------------- |
| `git reset --soft HEAD~1` | コミットを取り消すが、変更内容はステージングに残る |
| `git reset --hard HEAD~1` | コミットも変更内容もすべて消える                   |

`HEAD~1` は「直前の1つのコミット」という意味。`HEAD~2` なら2つ前まで戻せる。
`--hard` は変更が完全に消えるので、本当に不要なときだけ使うこと。

## ⭐️ git remote add origin URL

ローカルのリポジトリに**リモート（GitHub等）の接続先を登録する**コマンド。
`origin` はURLに対するエイリアス（別名）で、慣習的にこの名前を使う。

```bash
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
```

事前にGitHub上でリポジトリを作成し、表示されたURLをここに貼り付ける。

## ⭐️ git push

コミットした変更を**リモートリポジトリ（GitHub等）に送る**コマンド。

初回はローカルのブランチとリモートの紐付けが必要なので、以下を実行する：

```bash
git push --set-upstream origin main
```

- `origin` → リモートの接続先（エイリアス）
- `main` → 送るブランチ名
- `--set-upstream` → この組み合わせを記憶させるオプション

2回目以降は紐付けが済んでいるので `git push` だけでOK。

`--set-upstream` は **`-u`** と略せる。実際にはこちらをよく使う。

```bash
git push -u origin feature/login-screen
```

新しいブランチを作ってpushするときは、毎回この紐付けが必要になる。
→ PRを使った開発フローは [[GitHubとPR]]

## ⭐️ git pull

リモートの変更を**ローカルに反映する**コマンド。
実際には `git fetch` + `git merge` を一度にやっている。

チーム開発で同じファイルを別々に編集していた場合、**コンフリクト（競合）** が起きることがある。

## 🔧 git fetch

リモートの最新情報を**取得だけする**コマンド。ローカルのファイルには反映されない。
「リモートで何が変わったか確認したいけど、まだ自分のコードには反映したくない」というときに使う。

```bash
git fetch origin
```

## 🔧 git merge

今いるブランチに、**他のブランチの変更を取り込む**コマンド。
リモートのブランチの変更を取り入れたい場合、`fetch`をしてからじゃないと実行できない

```bash
git merge ブランチ名
```

## ⭐️ git status

今の作業状態を**一覧で確認する**コマンド。以下の情報が見れる。

- どのブランチにいるか
- ステージング済みのファイル（コミット対象）
- 変更はあるがステージングしていないファイル
- 新規作成でまだGitが追跡していないファイル

## ⭐️ git diff

**変更された箇所だけを差分として表示する**コマンド。
変更前の行が赤（`-`）、変更後の行が緑（`+`）で表示される。

## ⭐️ git log

**コミット履歴を確認する**コマンド。
`git log -p` で各コミットの変更内容まで見れる。
表示中は `q` キーで抜けられる。

| コマンド                    | 動作                                     |
| --------------------------- | ---------------------------------------- |
| `git log`                   | コミット履歴を表示                       |
| `git log -p`                | 変更内容付きで表示                       |
| `git log --oneline`         | 1コミット1行で簡潔に表示                 |
| `git log --graph --oneline` | 枝分かれの形（ブランチの分岐）を図で表示 |

`--graph` はマージ戦略（merge / squash / rebase）で履歴の形がどう変わるかを
目で確認するときに便利。→ [[GitHubとPR]]

## ⭐️ git branch

ブランチの**一覧表示や作成・削除**などを行うコマンド。
現在いるブランチには `*` がつく。

| コマンド                   | 動作                                             |
| -------------------------- | ------------------------------------------------ |
| `git branch`               | ブランチを一覧表示                               |
| `git branch ブランチ名`    | 新しいブランチを作成（切り替えはしない）         |
| `git branch -d ブランチ名` | マージ済みのブランチを削除                       |
| `git branch -D ブランチ名` | ブランチを強制削除（マージしていなくても消せる） |
| `git branch -m 新しい名前` | 今いるブランチの名前を変更                       |
| `git branch -a`            | リモートのブランチも含めて一覧表示               |

## ⭐️ git switch

ブランチを**切り替える**コマンド。

| コマンド                         | 動作                                 |
| -------------------------------- | ------------------------------------ |
| `git switch ブランチ名`          | ブランチを切り替える                 |
| `git switch -c 新しいブランチ名` | ブランチの作成と切り替えを同時にやる |

`git switch -c` は `git branch ブランチ名` + `git switch ブランチ名` を一発でやってくれる。

## ⭐️ git restore

**ファイルを元に戻す**コマンド。Git 2.23で `git checkout` から分離された。

| コマンド                        | 動作                                                   |
| ------------------------------- | ------------------------------------------------------ |
| `git restore ファイル`          | 編集を捨てて、直前のコミットの状態に戻す（**破壊的**） |
| `git restore --staged ファイル` | ステージングだけを取り消す（編集内容は残る）           |

`git restore ファイル` は**編集内容が完全に消える**ので注意。
`git add` を取り消したいだけなら `--staged` を付ける。

## ⭐️ git stash

今の作業中の変更を**一時的に退避する**コマンド。

| コマンド                         | 動作                                         |
| -------------------------------- | -------------------------------------------- |
| `git stash`                      | 変更を退避する                               |
| `git stash push -m "メッセージ"` | メッセージ付きで退避する                     |
| `git stash pop`                  | 退避した変更を元に戻す（スタッシュから削除） |
| `git stash list`                 | 退避中の変更を一覧表示                       |
| `git stash apply`                | 退避した変更を元に戻す（スタッシュは残る）   |
| `git stash drop`                 | 特定のスタッシュを削除                       |

## 🔧 git worktree

**1つのリポジトリから別の作業ディレクトリを作れる**コマンド。
ブランチを切り替えずに、別のフォルダで別ブランチの作業ができる。
今いるブランチに関係なく、指定したブランチのworktreeが作られる。

| コマンド                           | 動作                 |
| ---------------------------------- | -------------------- |
| `git worktree add パス ブランチ名` | 新しいworktreeを作成 |
| `git worktree list`                | worktreeの一覧を表示 |
| `git worktree remove パス`         | worktreeを削除       |

worktreeを削除してもブランチは残るので、不要なら `git branch -d ブランチ名` で別途削除する。
