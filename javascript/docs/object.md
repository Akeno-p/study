# JS では配列も関数もオブジェクトってどういうこと？

プレーンオブジェクトも、関数も、配列も、**全部「オブジェクト」というカテゴリーの仲間**。

## 結論

- JS の「オブジェクト」は **プロパティを持てる入れ物** という広い概念
- `{}`・関数・配列は、その**根っこを共有する3つの形**
- 違うのは、それぞれに乗っている **追加の能力** だけ
- ただの`{}`の名称はオブジェクトではなくプレーンオブジェクトというのが正しい名称(あんま呼ばれないらしい)

## 全部に共通する根っこ

```
オブジェクト(= プロパティを持てる入れ物)
├── {}     プレーンオブジェクト ← 素の状態
├── 関数   ← 「呼び出せる」能力が追加
└── 配列   ← 「数字キー + length + 配列メソッド」が追加
```

`typeof` で見ると、JS の内部での扱いが分かる。

```js
typeof {}; // "object"
typeof []; // "object"   ← 配列もオブジェクト扱い
typeof function () {}; // "function" ← ここだけ特別だが、内部的にはオブジェクト
```

## ケース① プレーンオブジェクト `{}`

「**素のオブジェクト**」。追加能力はなく、純粋にプロパティを持てるだけ。

```js
const obj = { name: "Taro", age: 20 };
obj.email = "taro@example.com"; // 後付けも自由
```

これが「オブジェクト」の一番ベーシックな形。

## ケース② 関数

「**呼び出せる能力 (`[[Call]]`)** がついたオブジェクト」。

```js
function test(a = 3) {
  let b = a + 5;
}
```

プレーンオブジェクト風に書くとこんな形。

```js
test {
  // 普通に見えるプロパティ
  name:      "test",
  length:    0,                // デフォルト値なしの引数の数
  prototype: { ... },

  // 内部の特別な情報(直接は見えない)
  [[Call]]:  function body,    // 中身: let b = a + 5;
  [[Scope]]: 定義スコープの情報,
}
```

- `[[ ]]` で囲まれた部分は、JS エンジンの内部だけが知っている領域
- 「呼び出せる」の正体は、この `[[Call]]` に関数本体のコードが入っているから
- `関数名()` の `()` は、**この `[[Call]]` を起動するスイッチ**

普通のオブジェクトと同じく、プロパティを自由に足せる。

```js
test.description = "テスト用の関数";
test.author = "Taro";

console.log(test.description); // "テスト用の関数"
console.log(test.name); // "test"  ← 最初から付いているプロパティ
console.log(test.length); // 0
```

## ケース③ 配列

「**数字キー + length + 配列メソッド**」がついたオブジェクト。

```js
const arr = ["みかん", "りんご", "ぶどう"];
```

プレーンオブジェクト風に書くとこんな形。

```js
arr {
  "0":    "みかん",
  "1":    "りんご",
  "2":    "ぶどう",
  length: 3,

  // 内部の特別な情報
  [[Prototype]]: Array.prototype,  // push, pop, map などのメソッドが入っている
}
```

意外なポイント。

- **インデックスは内部的には文字列キー**(`arr["0"]` でも取れる)
- **`length` は `push` などのメソッドが自動で更新する**
- **`push`, `map` などのメソッドは `Array.prototype` 側に置かれている**
- **プロパティの後付けもできる**(ただし普通やらない)
