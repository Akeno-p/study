# カスタムカラーパレットの作成

## なぜカスタムパレットが必要か

Tailwind のデフォルトパレット（`sky`、`indigo`、`slate` など）をそのまま使うと、**Tailwind を使っているプロダクトが全部似た色合いになる** という問題が起きる。

実際の現場では、ブランドの個性を出すために独自パレットを定義することの方がむしろ普通。Stripe の紫、Linear の青、Notion のグレー、いずれも独自パレット。

## 自前で 50〜950 を登録する書き方

`tailwind.config.js` で 1 色ずつ書く。

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        brand: {
          50: "#fef7ee",
          100: "#fdedd6",
          200: "#fad7ac",
          300: "#f7bb78",
          400: "#f39442",
          500: "#f0761f", // ブランドのメインカラー
          600: "#e15c15",
          700: "#bb4513",
          800: "#953817",
          900: "#783016",
          950: "#411609",
        },
      },
    },
  },
};
```

これで `bg-brand-500`、`hover:bg-brand-600`、`text-brand-900` のように、全シェードが Tailwind 標準と同じ感覚で使える。

## 「自前で 11 色を勘で決める」のは罠

11 シェードを手動でバランス良く並べるのはプロでも難しい。

- 明度の刻みが均等じゃないと「400 と 500 の差が大きすぎる」現象が起きる
- 彩度が暴れると「100 はピンクっぽいのに 900 は茶色」みたいなことになる
- アクセシビリティ（コントラスト比）も計算が必要

そのため現場では **ツールで生成 → 微調整** が定石。

## よく使われるツール

| ツール                                             | 特徴                                                               |
| -------------------------------------------------- | ------------------------------------------------------------------ |
| [uicolors.app](https://uicolors.app/)              | メインカラー 1 色入れると Tailwind 形式の 50〜950 を吐く。最も手軽 |
| [Tailwind Shades](https://www.tailwindshades.com/) | Tailwind のシェード設計思想に沿った生成                            |
| [Radix Colors](https://www.radix-ui.com/colors)    | アクセシビリティ前提で設計済みの完成パレット                       |
| Figma の Variables                                 | デザイナーが作ったトークンを開発側にも展開できる                   |

### 使い方の例（uicolors.app の場合）

1. ブランドカラー（例: `#f0761f`）を入力
2. 50〜950 まで自動生成される
3. コピペで `tailwind.config.js` に貼る

これだけで「個性 ＋ 一貫性」が両立できる。

## さらに発展：ブランドのパレット全体を持つ

実プロダクトでは、ブランド色だけでなく **グレーまで独自にする** ことも多い。

```js
colors: {
  brand:   { 50: '...', /* ... */ 950: '...' }, // ブランドカラー
  accent:  { 50: '...', /* ... */ 950: '...' }, // アクセント
  neutral: { 50: '...', /* ... */ 950: '...' }, // 独自のグレー
  success: { 50: '...', /* ... */ 950: '...' },
  warning: { 50: '...', /* ... */ 950: '...' },
  danger:  { 50: '...', /* ... */ 950: '...' },
}
```

Notion がグレーに微妙にベージュを混ぜているのは、こうやって独自のグレースケールを持っているから。これが「Tailwind 使ってるけど見た目が没個性じゃない」プロダクトの正体。

## 段階的な発展ルート

学習・実務のフェーズに合わせて、段階的に発展させていけば良い。

| ステージ                     | 戦略                                                 |
| ---------------------------- | ---------------------------------------------------- |
| 学習・試作                   | Tailwind デフォルトの `sky` `indigo` をそのまま使う  |
| 個人開発                     | `primary: colors.sky` でパレット参照                 |
| ブランド意識を出したい       | uicolors.app でブランド色から 50〜950 を生成して登録 |
| プロダクト・デザインシステム | デザイナーと組んで独自パレット全種を設計、Figma 連携 |

「Tailwind 使ってるシステムが全部おんなじような色になる」のは、ステージ 1〜2 で止まっている状態。ステージ 3 以降に進めば個性は十分出せる。

## 思想としてのまとめ

Tailwind は「制約のあるツール」ではなく、**「制約を設計するためのツール」**。

- デフォルトのパレットをそのまま使う → 無難で素早い
- パレットを別名で借りる → 意味付けが加わる
- 独自パレットを作る → 個性が出る

どこまでやるかは、プロダクトのフェーズと求められるブランド性で決めれば良い。
