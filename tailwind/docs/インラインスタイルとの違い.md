# インラインスタイルとの違い

## そもそもの疑問

「HTML を見ればスタイルが分かる」のが Tailwind の良さなら、インラインスタイルでも同じでは？

```jsx
// インラインスタイル
<button style={{ backgroundColor: '#0ea5e9', color: 'white', padding: '8px 16px', borderRadius: '6px' }}>
  送信
</button>

// Tailwind
<button className="bg-sky-500 text-white px-4 py-2 rounded">
  送信
</button>
```

「HTML でスタイルが見える」という点だけなら確かに同じ。でも決定的に違う点がある。

## 違い 1：レスポンシブ対応ができない

```jsx
// インラインスタイル：メディアクエリが書けない
<div style={{ fontSize: '14px' }}>  // スマホでもPCでも14px固定

// Tailwind：ブレークポイントが書ける
<div className="text-sm md:text-base lg:text-lg">  // 画面幅で変わる
```

インラインスタイルには `@media` に相当する仕組みがない。

## 違い 2：ホバーやフォーカス等の状態変化ができない

```jsx
// インラインスタイル：hover が書けない
<button style={{ backgroundColor: '#0ea5e9' }}>  // ホバー時に色を変えられない

// Tailwind：状態変化が書ける
<button className="bg-sky-500 hover:bg-sky-600 focus:ring-2">
```

`:hover`、`:focus`、`:active`、`:disabled` など、インラインスタイルでは対応できない。
JavaScript で `onMouseEnter` 等を使えば可能だが、CSS でやるべきことを JS で書くことになる。

## 違い 3：デザインの一貫性が担保できない

ここが一番大きい。

```jsx
// インラインスタイル：何でも書ける = バラバラになる
<div style={{ padding: '13px' }}>
<div style={{ padding: '15px' }}>
<div style={{ padding: '14px' }}>  // 全部微妙に違う

// Tailwind：決まった値しか使えない
<div className="p-3">   // 12px
<div className="p-4">   // 16px
                         // 13px や 15px は存在しない = ブレない
```

Tailwind は spacing も color も **用意された選択肢からしか選べない**。
これが「制約を設計するツール」と言われる理由。
インラインスタイルは完全に自由なので、チームで書くと必ずバラつく。

## 違い 4：ダークモード対応

```jsx
// インラインスタイル：ダークモードの仕組みがない
<div style={{ backgroundColor: 'white' }}>  // ダークモードでも白のまま

// Tailwind：1クラス足すだけ
<div className="bg-white dark:bg-gray-900">
```

## 比較表

| 観点                    | インラインスタイル         | Tailwind                  |
| ----------------------- | -------------------------- | ------------------------- |
| HTML でスタイルが見える | ⭕️                         | ⭕️                        |
| レスポンシブ対応        | ❌ できない                | ⭕️ `md:` `lg:`            |
| ホバー・フォーカス等    | ❌ できない                | ⭕️ `hover:` `focus:`      |
| デザインの一貫性        | ❌ 何でも書ける = バラつく | ⭕️ 決まった値しか書けない |
| ダークモード            | ❌ 仕組みがない            | ⭕️ `dark:`                |
| アニメーション          | ❌ `@keyframes` が書けない | ⭕️ `animate-`             |

## 結論：Tailwind はいいとこ取り

```
インラインスタイルの良さ（HTML で全部見える）
        ＋
CSS の良さ（レスポンシブ、ホバー、ダークモード等）
        ＋
デザインシステムの良さ（値の制約で一貫性を担保）
```

この **いいとこ取り** がユーティリティファーストの正体。

インラインスタイルは「CSS の全機能を捨てて値だけ書く」。
Tailwind は「CSS の全機能をクラス名で使える」。
表面的には似ているが、中身は全く別物。
