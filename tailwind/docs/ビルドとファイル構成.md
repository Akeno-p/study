# ビルドとファイル構成

## プロジェクトのファイル構成

```
tailwind/
├── node_modules/      ← npm が自動生成（Git 管理しない）
├── package.json       ← npm init で生成
├── package-lock.json  ← npm install で自動生成
├── input.css          ← 自分が書くファイル（入力）
└── output.css         ← ビルドで自動生成されるファイル（出力）
```

## input.css と output.css の役割

```
input.css   →   ビルド（CLI）  →   output.css
（人間 → ビルドツールへの指示書）    （ビルドツール → ブラウザへの完成品）
```

### input.css

自分が書くファイル。ビルドツールへの指示書。

```css
@import "tailwindcss";
```

「Tailwind の CSS を生成してね」という指示。HTML の `<link>` には output.css を書く、input.css はlinkに書かないためブラウザに渡らない。

### output.css

CLI が自動生成するファイル。HTML で実際に使われているクラスの CSS が全部入っている。

```html
<!-- HTML はこっちを読み込む -->
<link href="output.css" rel="stylesheet" />
```

ブラウザが読むのはこの完成品だけ。

## ビルドコマンド

### 1 回だけビルド（手動）

```bash
npx @tailwindcss/cli -i input.css -o output.css
```

HTML を変更したら、もう一度同じコマンドを実行する。

### 自動ビルド（ファイル監視）

```bash
npx @tailwindcss/cli -i input.css -o output.css --watch
```

`--watch` を付けると、HTML を編集するたびに自動で output.css が再生成される。
止めるときは `Ctrl + C`。

### コマンドの構造

```
npx @tailwindcss/cli -i input.css -o output.css
                      ↑ 入力ファイル  ↑ 出力ファイル
```

- `-i` = input（入力）
- `-o` = output（出力）

ファイル名は自由に変えられる。`-i src/styles.css -o dist/styles.css` のようにしても動く。
