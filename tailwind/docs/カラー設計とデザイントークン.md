# カラー設計とデザイントークン

## 「色や文字サイズを固定する」というルールは健在

UI の一貫性は「認知負荷」に直結するため、デザインシステムの基本ルールは Tailwind を使う場合でも健在。むしろ Tailwind を使う時こそ、その規律がより重要になる。

- 微妙に違う青が混在 → ユーザーが「これは別の意味？」と無意識に迷う
- 文字サイズがバラバラ → 情報の階層構造が伝わらない

「sky-500 を使う、sky-400 や blue-500 は使わない」というルールはデザインシステムの基本そのもの。

## Tailwind はこのルールを "強制しやすい" ツール

Tailwind は一見「クラスが自由に書ける＝バラバラになりそう」に見えるが、設定ファイルでパレットを絞り込める。

```js
// tailwind.config.js
module.exports = {
  theme: {
    colors: {
      primary: "#0ea5e9",
      secondary: "#64748b",
      danger: "#ef4444",
      white: "#ffffff",
      black: "#000000",
    },
  },
};
```

こうすると `bg-blue-500` や `bg-sky-400` は **そもそも書けなく** なる（クラスが存在しない＝CSS が生成されない）。

## デザイントークンという考え方

色を `sky-500` のような「見た目の名前」で使うより、**役割の名前**で使うのがベストプラクティス。

```html
<!-- イマイチ：sky-500 が何の青か分からない -->
<button class="bg-sky-500">送信</button>

<!-- 良い：役割が明確 -->
<button class="bg-primary">送信</button>
```

これが「デザイントークン」の考え方。

- ブランドカラーを変えたい時、config を 1 箇所変えれば全画面が変わる
- 「ここはなぜこの色？」が後から読んでも分かる
- ダークモード対応もしやすい

## 落とし穴：生のカラーコードを当てると色が散らばる

`primary: '#0ea5e9'` と単独で定義すると、**その 1 色しか手に入らない**。

実際の UI では、1 色だけでは足りないことがほとんど。

```html
<!-- 通常時 -->
<button class="bg-primary">送信</button>

<!-- ホバー時はちょっと濃く -->
<button class="bg-primary hover:bg-???">送信</button>

<!-- 背景に薄く敷きたい -->
<div class="bg-???">プライマリ系の通知</div>

<!-- 無効時 -->
<button class="bg-???" disabled>送信</button>
```

「濃く」「薄く」をその場の感覚でカラーコードを増やしていくと、結局色が散らばる。

## Tailwind パレットの真価

Tailwind の `sky-50` 〜 `sky-950` は、**全シェードが調和するように設計されたセット**。

```
sky-50   #f0f9ff   ← うっすい背景
sky-100  #e0f2fe
sky-200  #bae6fd
sky-300  #7dd3fc
sky-400  #38bdf8
sky-500  #0ea5e9   ← メイン
sky-600  #0284c7   ← ホバー用
sky-700  #0369a1
sky-800  #075985
sky-900  #0c4a6e   ← 濃い文字色
sky-950  #082f49
```

明度・彩度・トーンが連動していて、隣のシェードを使えば自然に「ちょっと濃い」「ちょっと薄い」が表現できる。自分で勘で選んだ濃淡ではこの一貫性は出ない。

## ベストプラクティス：パレットごと参照する

`primary` を 1 色のコードに固定するのではなく、`sky` パレットを丸ごと `primary` という名前で借りるのが定石。

```js
// tailwind.config.js
const colors = require("tailwindcss/colors");

module.exports = {
  theme: {
    extend: {
      colors: {
        primary: colors.sky, // primary-50 〜 primary-950 全部使える
        secondary: colors.slate,
        danger: colors.red,
      },
    },
  },
};
```

これは要するに **「`sky` というパレットを、`primary` という名前でも呼べるようにする」** という別名定義。

| 元の Tailwind クラス | 別名で書ける         |
| -------------------- | -------------------- |
| `bg-sky-50`          | `bg-primary-50`      |
| `bg-sky-500`         | `bg-primary-500`     |
| `text-sky-600`       | `text-primary-600`   |
| `border-sky-300`     | `border-primary-300` |

HTML 側ではこう書ける。

```html
<button class="bg-primary-500 hover:bg-primary-600 text-white">送信</button>

<div class="bg-primary-50 text-primary-900 p-4">プライマリ系の通知</div>
```

- `sky` の調和したパレットの恩恵は受けつつ
- 名前は意味ベース（`primary`）に置き換えられて
- ブランドカラーを変えたい時は `colors.sky` を `colors.indigo` に変えるだけ

## `extend` あり／なしの違い

書き方によって挙動が変わる点に注意。

```js
// パターンA: extend に書く → sky も primary も両方使える
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: colors.sky,
      },
    },
  },
};
```

```js
// パターンB: extend なしで書く → デフォルトパレットが消える
module.exports = {
  theme: {
    colors: {
      primary: colors.sky, // sky や red などは使えなくなる
    },
  },
};
```

| パターン | 用途                                               |
| -------- | -------------------------------------------------- |
| A        | 別名を足したいだけ、デフォルトも使いたい           |
| B        | プロジェクトで色をガチガチに縛る、間違いを防ぎたい |

`bg-blue-500` をそもそも書けなくしたい場合はパターン B。

## 色の定義方法の比較

| 定義方法                | 評価                                     |
| ----------------------- | ---------------------------------------- |
| `primary: '#0ea5e9'`    | △ 1 色しか取れず、ホバー等で色が散らばる |
| `primary: colors.sky`   | ⭕️ パレットごと借りるのが基本形          |
| `bg-sky-500` を直接使う | ○ 試作・個人開発なら全然アリ             |
