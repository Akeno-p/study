# セマンティック設計との両立

## きっかけになった疑問

Tailwind ではユーティリティファーストが思想なのに、`primary` のような役割名でクラスを定義したら、それはセマンティック CSS になるのでは？

→ 矛盾しているように見えて **「層が違う」** ので両立する。

## 2 つの "セマンティック" は別物

Tailwind が避けたいセマンティックと、推奨されるセマンティックは、対象が違う。

| 層                       | 例                                          | Tailwind の立場 |
| ------------------------ | ------------------------------------------- | --------------- |
| **値（トークン）の命名** | `primary` = `#0ea5e9`                       | OK・推奨        |
| **コンポーネントの命名** | `.submit-button { padding: ...; bg: ...; }` | NG              |

## 具体例で比較

### ❌ Tailwind が避けたい「セマンティック CSS」

```css
/* 1つのクラスに複数のスタイルが隠れる */
.submit-button {
  background: #0ea5e9;
  padding: 8px 16px;
  border-radius: 6px;
  font-weight: bold;
}
```

```html
<button class="submit-button">送信</button>
```

→ ボタンを見ても何が適用されているか分からない。CSS を開かないと判別できない。

### ⭕️ `bg-primary` を使う書き方

```html
<button class="bg-primary px-4 py-2 rounded font-bold">送信</button>
```

→ HTML を見れば全スタイルが見える。`primary` は **色の名前** であって、ボタンの定義ではない。

## つまり何が変わっていないか

`bg-primary` は **依然としてユーティリティ**。

- クラス 1 つ = スタイル 1 プロパティ（背景色だけ）
- HTML に並べて組み合わせる構造は変わらない
- 抽象化されたのは「色の値」だけで、「ボタンという概念」ではない

`sky-500` を `primary` に置き換えた瞬間も、書き方は

```html
<div class="bg-sky-500 text-white p-4">
  <div class="bg-primary  text-white p-4"></div>
</div>
```

完全に同じ形。**ユーティリティを HTML に並べる** という思想は崩れない。

## どこに線が引かれているか

Tailwind の本当の主張は

> 「コンポーネントの抽象化は CSS でやるな、**フレームワーク側（React/Vue）でやれ**」

```jsx
// 抽象化したいなら CSS じゃなくてここでやる
function PrimaryButton({ children }) {
  return (
    <button className="bg-primary px-4 py-2 rounded font-bold">
      {children}
    </button>
  );
}
```

こうすれば

- スタイルは HTML に見える（ユーティリティファースト維持）
- 繰り返しは関数で吸収できる（DRY も達成）
- 色の意味は `primary` で表現できる（デザイントークン）

3 つ全部成立する。

## まとめ

| 観点                                                       | 答え                                             |
| ---------------------------------------------------------- | ------------------------------------------------ |
| 値に意味のある名前を付ける（`primary`）                    | ユーティリティファーストに反しない               |
| スタイルの塊にコンポーネント名を付ける（`.submit-button`） | これが Tailwind の避けたい "セマンティック CSS"  |
| 抽象化したい時は？                                         | CSS ではなくコンポーネント（React 等）の層でやる |

「色の名前を変えただけ」と「スタイルの塊を隠した」は、見た目は似ているが **抽象化の層が違う** というのがポイント。
