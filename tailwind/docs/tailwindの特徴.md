# Tailwind の特徴

Tailwind は「ユーティリティファースト」という設計思想で、セマンティック（意味ベース）な命名とは対照的なアプローチを取る。

## セマンティック CSS との違い

**セマンティックな書き方（BEM など）**

```html
<div class="card">
  <h2 class="card__title">タイトル</h2>
</div>
```

クラス名が「これは何か（card、title）」を表す。

**Tailwind（ユーティリティファースト）**

```html
<div class="rounded-lg shadow-md p-4 bg-white">
  <h2 class="text-xl font-bold">タイトル</h2>
</div>
```

クラス名が「どう見えるか（角丸、影、余白）」を表す。

## それぞれの長所と短所

| 観点                       | セマンティック     | Tailwind         |
| -------------------------- | ------------------ | ---------------- |
| HTML の可読性              | 高い               | 低くなりがち     |
| CSS の設計コスト           | 高い（命名に悩む） | 低い             |
| スタイル変更の影響範囲     | 広がりやすい       | その場で完結     |
| 一貫性（デザインシステム） | 自前で頑張る       | 設定で強制できる |

## Tailwind が「あえて」非セマンティックな理由

- **命名問題からの解放**: `card-wrapper-inner-content` のような苦しい命名をしなくて済む
- **未使用 CSS の削減**: HTML に書いたクラスしか生成されない
- **デザインの一貫性**: spacing や color が設定ファイルで統一される

ただし、繰り返しが増える問題は、コンポーネント化（React/Vue など）や `@apply` で補う設計が前提になる。「HTML 側にスタイルを寄せる」という割り切りが Tailwind の本質。
