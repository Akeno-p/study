# Preflight（Tailwind のリセット CSS）について

`@import "tailwindcss";` を書いた時点で自動的に入ってくる、ブラウザのデフォルトスタイルを打ち消す仕組み。

---

## ⭐️ h1 を書いても文字が大きくならない

Tailwind を入れると、`<h1>` が `<p>` と同じ見た目になる。これは**バグではなく仕様**。

生成された `output.css` の中に、この記述が入っている。

```css
h1, h2, h3, h4, h5, h6 {
  font-size: inherit;    /* 親のサイズをそのまま継承 = 大きくならない */
  font-weight: inherit;  /* 太字にもならない */
}
```

`inherit` は「親要素の値を引き継ぐ」という意味なので、`<body>` と同じサイズ・同じ太さになる。

### だからサイズは自分で明示する

```html
<h1 class="text-2xl font-bold text-slate-900">nofeed-x</h1>
```

---

## ⭐️ なぜ打ち消すのか

**「意味」と「見た目」を分離するため。**

`<h1>` の意味は「最上位の見出し」であって、「大きい文字」ではない。
この 2 つは本来まったく別のこと。ブラウザが勝手に `<h1>` = 32px と決めているのは、意味と見た目を混同している状態。

Tailwind はこれを切り離す。

| | 誰が担当するか |
| --- | --- |
| **意味**（構造・SEO・スクリーンリーダー） | `<h1>` タグ |
| **見た目**（サイズ・太さ・色） | クラス（`text-2xl` など） |

**見た目をリセットしても `<h1>` の価値は 1 ミリも減らない。**
スクリーンリーダーは変わらず「見出しレベル 1」と読み上げるし、SEO にも効く。アクセシビリティの観点から `<h1>` を使う意味はそのまま残っている。

### 他にも理由がある

- **ブラウザ差異の排除** … Chrome / Safari / Firefox で `<h1>` のデフォルトサイズは微妙に違う。リセットすれば全部同じスタートラインに立てる
- **「書いたクラスだけが効く」の保証** … Tailwind の約束は「HTML を見れば見た目が全部分かる」こと。裏でデフォルトスタイルが効いていたら、その約束が破れる

---

## ⭐️ リセットされる主なもの

h1 だけではない。「Tailwind を入れたら全部崩れた」となるのは、全部これが原因。

| 対象 | どうなるか |
| --- | --- |
| `h1` 〜 `h6` | サイズも太さも継承（大きくならない） |
| `ul` / `ol` | **箇条書きの点・番号が消える**（`list-disc` で戻す） |
| `button` | ボタンに見えなくなる（枠も背景も無い） |
| `a` | 下線と青色が消える |
| すべての要素 | `margin` / `padding` が **0** |
| `img` | `display: block` になる |

**ゼロから自分で組み立てろ、という設計。**

---

## 🔧 リセットだけではなく「改善」もしている

Preflight は「素の HTML に戻す」のではなく、「モダンな開発の良い出発点を作る」もの。**足しているものもある。**

### box-sizing: border-box

```css
*, ::before, ::after {
  box-sizing: border-box;
}
```

CSS のデフォルトは `content-box` で、**`width: 100px` に `padding: 10px` を足すと実際の幅が 120px になる**（CSS の歴史的な設計ミスとして有名）。

`border-box` にすると padding を含めて 100px になり、直感通りになる。
世界中の開発者が CSS の 1 行目に必ず書いていたものを、Tailwind は最初からやってくれている。

### その他

- `<img>` を `display: block` にする（インライン要素だと下に謎の隙間ができる問題への対処）
- フォーム要素にフォントを継承させる（`<input>` だけ勝手にシステムフォントになるのを防ぐ）

つまり Preflight は「何もしない状態」ではなく、**「面倒な既知の罠をあらかじめ全部潰した状態」**。

## 📖 補足：Preflight は Tailwind の発明ではない

「打ち消しの CSS」は昔から存在していて、それを Tailwind が同梱しただけ。

| | 時期 | 何をするか |
| --- | --- | --- |
| **reset.css** | 2007 | 全部ゼロにする。過激派 |
| **normalize.css** | 2011 | **ブラウザ差異だけ**を埋める。デフォルトは残す穏健派 |
| **Preflight** | 現在 | normalize.css をベースに、さらに徹底的にリセット |

Tailwind 以前は、これを自分で選んで入れていた。
つまり「Tailwind の機能」というより **「Tailwind が選んだ前提」**。
