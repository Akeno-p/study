# PostgreSQL

サーバー型のデータベース。

## 特徴

- サーバー 1 台の中に、名前のついた DB を複数持てる
- ユーザー（ロール）と権限の管理がある
- 型が厳しい。数値の列に文字列を入れるとエラーになる
- 行単位でロックするため、同時書き込みに強い

## サーバーとクライアント

- サーバーは `postgres` プロセス。データを保管し、SQL を実行する本体
- クライアントは `psql` やアプリ。サーバーに接続して SQL を送るだけで、データは持たない
- 接続がない間のメモリ使用量は10~90MB、CPUは0~1%なので常駐させていてもんだない。

## DB

- 最初から `postgres`、`template0`、`template1` の 3 つがある。PostgreSQL 自身が使うもので触らない
- アプリ用の DB は自動で作られないので自分で作る必要がある。

## ユーザー（ロール）

- ユーザーは、DBサーバーにログインするためのアカウント
- アプリでも人間でも、DBに接続するときは必ずどれかのユーザーでアクセスする必要がある。
- 公式ドキュメントでは「ロール」と呼ぶ。`CREATE USER` は `CREATE ROLE ... LOGIN` の別名

| 権限             | できること                                         |
| ---------------- | -------------------------------------------------- |
| スーパーユーザー | サーバー全体で無制限。所有者かどうかは関係ない     |
| DB の所有者      | その DB の中では何でもできる。他の DB には触れない |
| 一般             | 明示的に許可された操作だけ                         |


## ユーザーと DB を作る

```sql
CREATE USER app WITH PASSWORD 'パスワード';
CREATE DATABASE app OWNER app;
```

- DB 名とユーザー名を同じにするのは慣習。接続先 DB を省略するとユーザー名と同じ DB に接続する
- 名前はアンダースコアを使う。ハイフンは引用符が必要になる
- 文字列はシングルクォート。ダブルクォートは名前の引用という別の意味

## psql

PostgreSQL を操作するコマンド。中に入って SQL を打ち、`\q` で抜ける対話型。

| コマンド                          | 動作                                 |
| --------------------------------- | ------------------------------------ |
| `psql postgres`                   | postgres DB に接続                   |
| `psql -U app -d app -h localhost` | ユーザー・DB・TCP を指定して接続     |
| `psql -d app -c "SELECT 1;"`      | 1 回だけ実行して抜ける               |


- プロンプト `postgres=#` の前半は接続中の DB 名。`#` はスーパーユーザー、`>` は一般ユーザー
- `postgres-#` は `;` を打っていないので続きを待っている状態。`\r` で捨てられる
- SQL は末尾に `;` が必要。`\` で始まる psql のコマンドは不要
- psql の中でターミナルのコマンドは打てない。SQL として送られて構文エラーになる

| コマンド        | 意味                     |
| --------------- | ------------------------ |
| `\l`            | DB の一覧                |
| `\dt`           | 今いる DB のテーブル一覧 |
| `\d テーブル名` | 列や制約                 |
| `\q`            | 抜ける                   |

## 接続経路

- **TCP**: `-h localhost` を付けたときの経路。宛先は「IP アドレス + ポート番号」で、標準ポートは `5432`。相手が同じマシンでも別マシンでも同じやり方で届く
- **ソケットファイル**: `-h` を付けないときの経路。同じマシン専用で速いが、別マシンには届かない

同じマシンでも TCP で `localhost` を指定するのが慣習。設定の形を環境ごとに変えずに済む。
