# Turso

SQLite をベースにした DB のホスティングサービス。
SQLite をフォークした libSQL を Turso のサーバー上で動かし、アプリからは HTTP でクエリを送って使う。SQL の書き方は SQLite と同じ。

## 特徴

- DB はアプリサーバーではなく Turso のサーバー上にあるため、アプリサーバーを複数台にしても同じ DB を共有できる
- SQLite と同じ文法で書ける
- 軽量なので DB を大量に作れる（ユーザーごと・顧客ごとに DB を1つずつ、など）
- アプリサーバーに DB のコピー（埋め込みレプリカ）を置き、読み込みをローカルファイルの速さにできる
- SDK は JavaScript / TypeScript が中心

## 埋め込みレプリカ

各アプリサーバーが DB のコピーをローカルファイルとして持つ仕組み。

- 読み込み：ローカルのコピーから読む
- 書き込み：Turso のサーバー（本体）に送る。本体で1つずつ処理される
- 各サーバーは定期的に本体から差分を取ってきてコピーを更新する

書き込みが他のサーバーのコピーに届くまで数秒のラグがあるため、投稿直後に別のサーバーに繋がると「見えない」ことが起こり得る。速くなるのは読み込みだけで、書き込みはネットワーク越し。

## 向いているケース

読む人が多く、書く人は少なく、数秒の反映遅れが問題にならないサービス。

- ブログ・ニュース・ドキュメントサイト
- 短縮 URL、辞書などの参照系 API
- Cloudflare Workers などのサーバーレス環境（HTTP でクエリを送るだけなので相性が良い）

## 向いていないケース

- SNS、チャットなど、書き込みが多く即座に反映される必要があるもの
- 注文・決済・予約など、データが一瞬でも食い違うと困るもの
