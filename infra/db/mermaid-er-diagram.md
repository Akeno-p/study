# Mermaid でER図を書く

ER図はテキストで書ける。Mermaid という記法を使うと `.md` ファイルの中に直接書け、GitHub 上ではそのまま図として表示される。図をドキュメントと一緒に Git 管理できるのが利点。

記号（`||`, `o{` など）の意味は [er-diagram.md](./er-diagram.md) を参照。ここでは「どう書くか」をまとめる。

## 全体の骨組み

`erDiagram` と宣言し、その下にインデントして中身を書く。

```
erDiagram
    （ここに「線」と「箱の中身」を書く）
```

## リレーション（線）の書き方

型はこの通り。

```
左エンティティ  [左の記号][線][右の記号]  右エンティティ : "ラベル"
```

例:

```
erDiagram
    User ||--o{ Post : "投稿する"
```

- 記号（`||`, `o{` など）の意味は er-diagram.md 参照
- ラベルは関係の説明。省略可
- 記号の書く順番は**左が最大で右が最小**(右側は逆)
- 基本的に親を左、子を右に書く。

### 線は2種類

| 線        | 呼び方     | 意味                                     |
| --------- | ---------- | ---------------------------------------- |
| `--` 実線 | 識別関係   | 親がいないと子が存在できない強い結びつき |
| `..` 点線 | 非識別関係 | 親と切り離しても子が単体で存在できる     |

最初は全て `--`（実線）で問題ない。

## 属性（箱の中身）の書き方

箱の中にカラムを書くときは `{ }` で囲む。**型 → 名前 → キーの印** の順。

```
User {
    bigint id PK
    string username
    string name
}
```

キーの印は3種類。

| 印   | 意味                    |
| ---- | ----------------------- |
| `PK` | 主キー（Primary Key）   |
| `FK` | 外部キー（Foreign Key） |
| `UK` | ユニークキー            |

## 全体の例

線と箱を両方書くとこうなる。

```
erDiagram
    User ||--|| Account : "認証情報"
    User ||--o{ Post : "投稿する"

    User {
        bigint id PK
        string username
    }
    Account {
        bigint id PK
        bigint user_id FK
    }
    Post {
        bigint id PK
        bigint author_id FK
        text   body
    }
```

## ライブプレビュー

書きながら図を確認するには **Mermaid Live Editor**（mermaid.live）が手軽。ブラウザで開くだけ、インストール不要で、左に打つと右にリアルタイムで図が出る。VS Code なら Mermaid 対応の拡張を入れると、Markdown プレビュー内でも図が表示される。
