# Webサーバー

インターネットからのアクセスを最初に受け取るソフト。例: Nginx、Apache。

## 仕事は2つ

1. 静的ファイル（CSS・JS・画像など）を自分で返す
2. それ以外のリクエストを、後ろのアプリケーションサーバー（[application-server.md](application-server.md)）に中継する

```text
ブラウザ -> Webサーバー ─ 静的ファイル用のURL -> 自分でファイルを返す
                        └ それ以外のURL       -> アプリケーションサーバーに渡す
```

プログラムを動かす機能はない。

## 何が得意か

**軽い仕事を大量に処理すること。**

- 同時に数千以上のリクエストを処理できる
- ファイルを返す時は、ディスクからそのまま流す

大量に処理できるのは、やっている仕事が「ファイルをそのまま流す」「別のソフトに中継する」という軽いものだけだから。

## URLの先頭を見て振り分ける

Webサーバーは「これは静的ファイルか、プログラムの実行か」を中身で判断しているわけではなく、**URLの先頭の文字列（例: `/static/`）**を見てい振り分けている。

どのURLをどう扱うかは、Webサーバーの設定ファイルに自分で書く。

## Webサーバーを置くメリット

| メリット | 内容 |
| --- | --- |
| 通信が遅い相手から処理係を守る | アプリケーションサーバーの処理係は、相手との通信が終わるまでその1件にかかりきりになる。Webサーバーを手前に置くと、遅い通信の相手はWebサーバーが引き受け、アプリケーションサーバーにはデータが揃ってからまとめて渡してくれる |
| HTTPSの処理 | Let's Encryptの証明書を取得・自動更新するツールは、Webサーバーと連携する前提で作られているため、Webサーバーに置く方が楽 |
| 複数アプリの振り分け | 80番・443番ポートは1つのプロセスしか使えない。Webサーバーが入口になってドメインやURLの先頭で振り分けるので、1台のマシンで複数のアプリを公開できる |
| アプリ停止中も応答できる | アプリケーションサーバーを再起動している間も、Webサーバーがエラーページやメンテナンス画面を返せる |
| 圧縮 | レスポンスの圧縮をWebサーバーが引き受けるので、アプリケーションサーバーの処理係は圧縮を待たずに次のリクエストに移れる |
| キャッシュ | 保存しておいた応答をWebサーバーが返すので、同じリクエストがアプリケーションサーバーに届かず、処理係を使わずに済む |
| アクセス制限・リクエスト制限 | 拒否するリクエストをWebサーバーが止めるので、アプリケーションサーバーに届かず、処理係を使わずに済む |
| リダイレクト | HTTP→HTTPSの転送などをWebサーバーが設定だけで行うので、アプリケーションサーバー側で転送用の処理や待ち受けを用意しなくて済む |


## Webサーバーが返すエラー:

| 番号 | 名前            | 意味                                                                 |
| ---- | --------------- | -------------------------------------------------------------------- |
| 502  | Bad Gateway     | アプリケーションサーバーから正常な返事をもらえなかった               |
| 504  | Gateway Timeout | アプリケーションサーバーにつながったが、制限時間内に返事が来なかった |

### 502 Bad Gateway

リクエストを渡そうとしたが、つながらない、または接続を断られた場合。

- アプリケーションサーバーが起動していない、または異常終了している
- 処理に時間がかかりすぎて、ワーカーが強制終了された
- 待ち行列が満杯で、接続を受け付けてもらえない
- Webサーバーの設定で、アプリケーションサーバーの場所の指定が間違っている

### 504 Gateway Timeout

リクエストを渡せたが、返事を待っている間に制限時間を過ぎた場合。

- 処理係が全部塞がっていて、順番が回ってこない
- アプリの処理そのものに時間がかかりすぎている

制限時間は、Nginxの場合は初期設定で60秒。この時間には「待ち行列で処理係が空くのを待っている時間」と「処理係が処理している時間」の両方が含まれる。


※ 処理係 = 同期サーバーならワーカーやスレッドのこと。非同期サーバーならワーカーのこと。このドキュメント内の呼び方であって、存在する呼び方ではない。
