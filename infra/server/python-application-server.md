# Python のアプリケーションサーバー

## ワーカーとスレッドの考え方

Python は、1つのワーカーの中で同時に計算できるスレッドが1つだけ（GIL という制約）。そのため、ワーカーとスレッドの役割が分かれる。

| 増やすもの | 役割                                                                 |
| ---------- | -------------------------------------------------------------------- |
| ワーカー   | 並列に計算する数。コアを使い切るために、並列で処理したい数だけ立てる |
| スレッド   | DB や外部 API の返事を待っている時間に、別のリクエストを進める       |

- **ワーカー**: コア数を目安に決める。上限はメモリ。ワーカーの数の目安として、Gunicorn の公式ドキュメントでは `(2 × コア数) + 1` が挙げられている。
- **スレッド**: 待機時間に他の処理を実行できるだけなので、並列実行されるわけではない。

※ GIL（Global Interpreter Lock）: Python 本体に「同時に1つのスレッドしかコードを実行できない」という鍵がかかっている仕組み。

## よく使われるアプリケーションサーバー

| 方式   | よく使われるもの |
| ------ | ---------------- |
| 同期   | Gunicorn         |
| 非同期 | Uvicorn          |

### Gunicorn + Uvicorn

管理役を Gunicorn、ワーカーを Uvicorn にする組み合わせもよく使われる。Gunicorn の管理役の機能（ワーカーの起動・監視・立て直し）を使いつつ、ワーカーは非同期にできる。

## Gunicorn の主な設定

| 設定                     | 指定の仕方        | 初期値 |
| ------------------------ | ----------------- | ------ |
| ワーカーの数             | `--workers 3`     | 1      |
| 1ワーカーあたりのスレッド | `--threads 4`    | 1      |
| 1件の処理の制限時間      | `--timeout 30`    | 30秒   |
| 待ち行列に並べる数の上限 | `--backlog 2048`  | 2048件 |
