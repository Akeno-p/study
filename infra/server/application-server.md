# アプリケーションサーバー

アプリのプログラムを動かして、結果を返すソフト。

アプリを書いた言語ごとに、使うソフトが違う。

| 言語   | 例                       |
| ------ | ------------------------ |
| Python | Gunicorn、uWSGI、Uvicorn |
| PHP    | PHP-FPM                  |
| Ruby   | Puma                     |

## 何が得意か

**プログラムを動かすこと。**

その代わり、同時に処理できる数は少ない。
性能が低いわけではなく、「プログラムを動かす」という仕事そのものが重い。

## ワーカー（処理係）

多くのアプリケーションサーバーは、**デプロイしたアプリをコピーしたプロセスを決まった数だけ立ち上げておき**、それぞれがリクエストを処理する。この処理係をワーカーと呼ぶ（呼び方はソフトによって違う）。

```text
アプリケーションサーバー
├── 管理役（1つ） … 自分ではリクエストを処理しない
├── ワーカー     … アプリを読み込んでリクエストを処理する
├── ワーカー
└── ワーカー
```

- **管理役**: ワーカーを起動し、ワーカーが異常終了したら新しく立ち上げ直す
- **ワーカー**: それぞれがアプリを丸ごと読み込んでいて、リクエストを受け取ってプログラムを実行し、結果を返す

1つのワーカーは、1件のリクエストを処理している間は他のリクエストを受けられない。ワーカーが3つあれば、3件まで同時に処理できる。

※ プロセスとは 実行中のプログラム1つ分のこと。

### ワーカーの数は固定

ワーカーの数は起動時に指定した数のまま変わらない。3つと指定したら、アクセスが0件でも100件でもワーカーは3つ。今アクセスされている数のことではない。

### 割り振りは「人ごと」ではなく「リクエスト1件ごと」

ワーカーが担当するのは、人や端末ではなく、1件のリクエスト。

1. ブラウザが「この処理をしてください」とリクエストを送る
2. 空いているワーカーがそれを受け取る
3. プログラムを実行して、結果を返す
4. そのワーカーは空きに戻る


### ワーカー3つ = 利用者3人まで、ではない

同時に処理できる数が3件までという意味で、利用者数が3人までというわけではない。

### ワーカーが全部塞がっている時に次のリクエストが来たら 待ち行列に並ぶ

エラーにはならず、待たされる。

リクエストは待ち行列に入り、どれかのワーカーが空いた時点でそのワーカーに処理される。
1件の処理は0.1秒前後で終わるので、待たされたことにはまず気づかない。

ただ待ち時間が長すぎたり、並んでいるリクエストの数が多すぎたりするとエラーになる。

- 待ち時間が長すぎて、Webサーバー側の制限時間を超えた -> 504
- 待ち行列が満杯で、並ぶこともできなかった -> 502

## ワーカーの数はメモリで決まる

ワーカー1つは **アプリ全体を読み込んだプロセス** なので、1つあたり数十〜100MB程度のメモリを使う。
当たり前だが、機械のメモリに収まる数までしか立ち上げられない。

### ワーカー数を固定する意味

アクセスのたびにプロセスを新しく起動する作りだと、アクセスが殺到した時にプロセスが際限なく増えて、メモリが尽きる。ワーカー数を固定しておけば、使うメモリに上限ができるのでそれを防げる。

## 時間がかかりすぎているワーカーは強制終了される

管理役は各ワーカーを監視していて、1件の処理が制限時間を超えると **そのワーカーを強制終了** し、**新しいワーカーを立ち上げ直す**。

強制終了された処理を待っていた利用者には **502エラー** が返る。

### 時間がかかりすぎる原因の典型例

- **無限ループ**: 終了条件を間違えた `while` など
- **外部のAPIを呼んで、相手から返事が来ない**
- **データベースの処理が終わらない**: 大量のデータを一度に取得する問い合わせなど
